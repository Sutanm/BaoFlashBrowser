# 提问话术：Electron 自绘浮层（WebContentsView）冷启动体验改善

> 用途：拿去问社区 / 同事 / 其他 AI。自包含，对方无项目上下文也可读。
> 数据标注：【实测】= 本机探针跑过；【量级】= 经验值，未实测。

## 背景一句话

Electron 39 + Vue 3 的 Flash 浏览器（多标签，页面用 WebContentsView 做进程隔离），自绘浮层（下拉面板 / 快捷设置 / toast）也是 WebContentsView，**首次打开要 160–290ms，预热后 20–25ms**——在"预热不划算"的前提下，还有什么办法改善首次打开的体验？

## 架构与约束（为什么绕不开）

- 浮层必须是 `WebContentsView`：页面是原生子视图，外壳的 DOM（Vue）盖不住它（Electron 合成模型：DOM 与原生视图是两个世界），自绘浮层只能再叠一个原生层。
- 页面必须进程隔离：跑 PPAPI Flash（自维护的内核 patch，按单实例设计）或注入 Ruffle（按页面会话注入），崩溃域必须与 UI 分开。这是功能需求。
- 浮层不能少渲染：自绘是硬需求（自绘主题开关、整行高亮焦点环），原生 `Menu.popup` 画不出来。
- 【实测】每个 WebContentsView 独占渲染进程，**同站也不合并**；空页面 renderer 69–72 MB working set（Windows）。
- 冷启动 260ms 的构成【量级，未做分段埋点】：建渲染进程 + 文档加载/Vue 启动 + 首帧（隐藏视图重新显示要重建合成面）。

## 已实测 / 已否决的方案（避免重复推荐）

| 方案 | 结果 | 否决理由 |
|---|---|---|
| 悬停预热（pointerenter） | 现状默认档 | 悬停到点击通常 100–300ms，不够建进程+首帧，首次打开还是冷 |
| 预热前移（外壳首帧后 idle 预热 + 5 分钟回收） | 否决 | 用户可能根本不点，预热期间空占 69–72MB——这正是当初选悬停预热的原因 |
| always 常驻预热 | 有此选项但非默认 | 同上，内存常驻 |
| `webContents.clone()`（复用源渲染进程，唯一零进程成本入口）【实测可行】 | **否决** | 共享渲染进程与 PPAPI Flash 单实例、Ruffle 按页面会话注入正面冲突（语义破坏） |
| 外壳 DOM 动画掩盖（自适应 transition：按下反馈 + 工具栏下缘投影渐入，面板到达即交接） | 做了可交互 demo 实测 | 技术上成立，但**冷开/热开差异仍可感知**，用户会察觉"莫名的抖动卡顿" |
| 换 CEF / 魔改内核做 surface embedding（页面纹理进 DOM） | 评估过 | 万行级 C++、viz 接口不稳定、每版本重放；且页面进 DOM 前提撞 PPAPI |
| 浮层进程池（多个浮层共享一个渲染进程） | 无收益 | 浮层已合并为单一视图（panel/quick/toast 共用一个 WCV） |

## 我目前还开着的思路（欢迎补充/拍砖）

1. **0-patch keepalive 实验**：预热视图保持 `setVisible(true)` 但 bounds 放窗口外（或 1×1），赌 Chromium 对"可见但在窗口外"的视图仍保持合成面 → 打开时省掉 surface 重建。未验证，不确定窗口外视图是否被裁剪不合成。
2. **内核 patch：给 WebContentsView 补 `paintWhenInitiallyHidden` 等价物**（BrowserWindow 有、WCV 没有）——隐藏期保持 compositor frame sink，消除"重新显示要重建合成面"那段。属于小 patch，但想先用思路 1 验证收益段再决定立项。
3. **`--process-per-site` / `--renderer-process-limit` 开关实验**：标签内存方向，与浮层无关但同属进程模型。注意 process-per-site 若真的合并同站进程，会撞上面 Flash 单实例的墙（和 clone 同款风险）。
4. 高频简单浮层（右键菜单类）改原生 `Menu.popup`，自绘需求重的保留 WCV——局部止血。

## 问题定义（压缩版）

> 在「页面必须独立渲染进程隔离（Flash 崩溃域）+ 浮层必须自绘 Web（原生控件画不出）+ 不接受空占一份 renderer 内存（69–72MB）」三条约束下，如何改善 WebContentsView 浮层的首次打开体验（实测冷启 160–290ms，预热后 20–25ms）？
> 崩溃域合并（clone/进程池）、动画掩盖（冷热差异可感知）、常驻预热（空占内存）均已实测否决。
> 体验目标：要么首次打开进入"无感"档（<100ms），要么有可靠的感知优化且不产生冷热不一致。

## 环境

Windows 11，Electron 39.8.10（自维护 PPAPI patch），sandbox renderer，浮层视图透明背景 + 圆角投影面板，打开有 140ms 淡入缩放动效。
