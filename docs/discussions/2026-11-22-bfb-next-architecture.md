## 1. 产品边界

Next 是从空白构建的 Flash 浏览器。首个目标是让用户在新的浏览器外壳中可靠打开、操作和恢复 Flash 标签，用实际游戏和可重复的本地样本验收。已定的产品方向包括原生 PPAPI 与 Ruffle 双引擎、WebContentsView、Vue 3、Fluent 2 视觉语言、顶部两行布局、Chrome 式标签交互、64 位和暂缓 Modern。现有项目提供需求、故障案例和回归样本。

Win x64 首期开发使用自编译 Electron 39.8.10 / Chromium 142.0.7444.265，内核标签为 `bao-v142-265-verified`。现有发布配置已通过 JavaScript 桥、Stage3D AUTO/SOFTWARE 和火线精英启动链路验证。其他 OS、更多站点以及 Next 宿主中的 Flash 行为单列验证。 [142 真机报告 §10.16](../reports/2026-11-21-142-flash-runtime.md)

## 2. 内核和发布边界

- **工程基线**使用已验证的 39.8.10 发布配置。开发可直接调用现有自编译二进制。记录 Electron、Chromium、依赖修订、补丁序列、构建参数及产物和插件的 SHA-256；已知产物用于回归对照。运行时的独立重建和发布依赖校验仍需完成。
- **发布基线**另行审定。Electron 39 已于 2026-05-05 结束上游支持。对任意站点发布前，以实际维护能力决定可发布范围，记录安全修复跟踪与响应责任、构建与分发完整性、可恢复的更新渠道和停止分发条件。原生 Flash 的来源、再分发许可和平台覆盖需独立确认。验证包先采用独立目录及受控测试范围。 [Electron 发布计划](https://releases.electronjs.org/schedule) · [39.8.10](https://releases.electronjs.org/release/v39.8.10) · [Adobe Flash EOL](https://www.adobe.com/products/players/flash-player-distribution.html)
- **后台渲染补丁**按 Next 宿主的可复现故障决定。本地 HTML 的 #52844 对照共 6 轮、24 个用例，5 轮全部通过。剩余 1 轮默认节流与关闭节流均无法截图，调整视图尺寸后恢复。现有结果支持暂缓 #52844，待实际 Flash 标签复测。#54311 随运行时恢复节流的需求验证，#54090 随隐藏跨导航停帧复现验证。这些验证可与外壳开发并行。 [52844](https://releases.electronjs.org/pr/52844) · [54311](https://releases.electronjs.org/pr/54311) · [54090](https://releases.electronjs.org/pr/54090)

## 3. 外壳、标签与隔离

| 边界 | 实现合同 |
| --- | --- |
| 主进程与窗口 | 主进程拥有窗口、标签顺序、选中关系、导航命令、引擎和站点权限。每个标签有稳定业务 ID，WebContents 重建时更新绑定代际。页面事件先核对绑定，窗口关闭主动关闭其拥有的 WebContents。跨窗口移动保留业务 ID，移动失败可回到原窗口。 |
| 页面 | 每个已加载标签使用 WebContentsView。将进程与站点隔离视为 Chromium 行为，依目标配置验证。区分选中、可见、加载、崩溃、未加载和销毁后重建。Flash 和会话仍在运行的标签受资源保护。冻结与后台持续出帧随实测落地。 |
| 引擎 | 默认与站点规则决定初始引擎；用户手动切换时可确认记为站点规则。切换使用新 WebContents，先验证 E39 导航栈恢复；记录无法还原的状态，失败要提供可理解的恢复动作。Ruffle 使用版本固定的本地资源，验证 WASM、子帧、CSP 与 SWF 网络链路。PPAPI 启用范围、版本通告、站点兼容规则和沙箱例外按当代证据逐项决定。 |
| 权限与会话 | 外壳使用本地受信任来源与精简 preload。远程页面默认关闭 Node，开启 context isolation、sandbox、webSecurity。内部 UI、真实用户 profile 与测试 profile 分开。每个可访问外部内容的 Session 同时接权限检查与请求，按请求来源及嵌入来源处理。对弹窗、新窗口、导航及外部协议设显式策略。插件隔离无法满足时，限制能力和验证范围并重新评审。 |
| IPC | 异步命令与投影事件。公共合同校验输入和发送者身份，按窗口和资源归属授权。错误只返回稳定代码与允许公开的详情。页面不获得外壳 IPC 桥。可使用少量类型化事件通知外壳拉取快照，协议随实际负载升级。 |
| 外壳 | Vue 3 + Pinia，局部交互保存在组件内。Fluent 2 token 组织颜色、状态与尺寸，两行布局。Reka UI 与 Ark UI 用实际菜单、对话框及焦点行为比较。先在壳内解决对话框，必须覆盖页面区域时验证一个受信任 WCV 浮层。文件选择、系统通知及 OS 凭据验证使用平台能力。 |

标签合同包含撤销关闭、恢复上次会话和未加载占位。标签固定、关闭、静音、复制、排序、拖出窗口及后续分组与搜索沿用用户提出的交互目标。分别验证 SPA、重定向、登录、前进/后退、F11、焦点、键盘输入和 IME；使用 E39 的 `navigationHistory` 试验引擎切换和恢复，包括 HTTPS、POST、历史位置以及恢复失败。切换时验证旧页面的迟到事件不会污染新页面。 [E39 导航历史](https://github.com/electron/electron/blob/v39.8.10/docs/api/navigation-history.md) · [E39 Session](https://github.com/electron/electron/blob/v39.8.10/docs/api/session.md) · [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

## 4. 数据和基础模块

| 模块 | 首选路径与开工条件 |
| --- | --- |
| 浏览数据 | Next 独立 userData。站点存储和 cookies 由 Chromium 管理。SQLite 为应用数据候选，持久化历史、书签、设置、下载及会话。主进程持业务权威，数据库任务根据延迟结果选择执行位置。迁移事务化，定期备份与恢复在真实磁盘上验证，清理按数据类别执行。 |
| 下载 | 先验收 Chromium 下载的身份、分区、代理、暂停和恢复行为。aria2 扩展到经过验证的请求类型。IDM 引擎方向保留，按官方接口和可管理性另立验收。原生下载被取消前明确交接所有权，失败避免重复请求或意外降级。 |
| i18n 与更新 | 共享词典和单一语言状态，构建检查 key、参数与缺失翻译。更新仍采用通知模式作为建议，按产品线和用户选择的稳定/测试渠道识别资产。使用独立 app ID、userData 与产物元数据。 |
| 密码 | 待新评审。E39 同步 safeStorage 可作为候选，验证后端强度、主线程耗时及恢复语义。没有可信密钥后端时默认停用保存。门禁在解密前，任何解密失败都保留密文及密钥。旧数据迁移采用用户触发的单独入口，失败不得修改来源。 |
| 扩展与脚本 | Violentmonkey 是用户选定的优先方向。先在同一 E39 构建确认 MV3 能力、`userScripts` 缺口、隔离、权限撤销、worker 重启和 GM API。参考上游与现有垫片，再决定补齐范围、许可和维护成本。商店、通用 CRX 和 Native Messaging 各自按实际需求立项。 |
| DevTools / CDP | 原生 DevTools 优先。内部 CDP 先使用 Electron 的 `webContents.debugger`，目标绑定显式化。先做一个消费者，用上游方法验证 OOPIF、导航与 DevTools detach。出现第二位消费者后再扩展所有者、订阅及副作用仲裁。响应使用原生 Promise，事件有界，各代际失效及时通知，断开阶段的指令明确失败。 |

SQLite 单写者与 WAL 的基本验证覆盖迁移中断、磁盘满、恢复、事务、备份和清理失败。日志默认只记录运行所需的最少信息，崩溃转储本地收集与保留单独配置。密码、带认证信息的 URL、完整 CDP 消息及敏感帧不进入常规日志。 [SQLite Backup](https://sqlite.org/backup.html) · [E39 safeStorage](https://github.com/electron/electron/blob/v39.8.10/docs/api/safe-storage.md) · [E39 扩展 API](https://github.com/electron/electron/blob/v39.8.10/docs/api/extensions.md) · [E39 Debugger](https://github.com/electron/electron/blob/v39.8.10/docs/api/debugger.md)

## 5. 自动化与后续 Agent

自动化从真实 Flash 工作流逐步构建。先验证后台出帧与输入回环，再决定视觉、OCR 与脚本边界。截图元数据记录采集来源、目标、裁剪原点、坐标关系和有效代际；坐标变换经实际图案和实际输入回环验收。E11 四组结果保留为对照。在 142 上测试缩放、跨屏、后台、视图移动、引擎切换和采集过程中状态变化。模板、找色、OCR 以游戏样本误判、负载和冷启动实测排序。

自动化包和 IR 重新定义。先让最小本地工作流通过受限接口处理一个真实用例，再评审共享包沙箱。对 QuickJS/Wasm 与独立进程的候选，验证越权拒绝、超时终止、请求取消、内存预算和持久状态保护。录制作为后续功能，评审范围、保留期、删除和敏感内容，限制捕获、编码及内存峰值。

Agent 保留为后续产品方向。第一阶段研究范围限于独立测试 profile 的本地只读观察和确定性验收。共享登录态、外部模型传输和页面写操作分别进入独立安全评审。观察结果携带采集时间与文档身份，同时在 UI 显示正在进行的任务和控制状态。使用本地 fixture 验证权限与生命周期，业务能力按通过范围逐步开放。

**分层（2026-11-23 定）**：本节是**对外承诺与安全边界**——独立 profile、只读优先、共享登录态/外部模型传输/页面写操作各自独立评审。Agent 的**实现合同**（工具面分层、权限三级、资源闸、会话模式、目标绑定）见 [11-21 讨论稿 §F](2026-11-21-bfb-next-architecture.md)，并受其 F3 审计约束。两者口径不一致时：**本节约束对外承诺，§F 约束实现细节**；§F 中标记【待审计】【冻结至 M3】的条款不得作为对外表述。

## 6. 交付顺序和验收

**现在可以开工。** 首个实现增量用现有 Win x64 运行时拉起 Vue 外壳，让主进程管理两个 WCV 标签，跑通地址栏导航、标签切换、焦点交接与关闭。用独立测试 profile 验证普通 HTML 和本地 PPAPI 样本，覆盖窗口销毁和重建后旧事件隔离。通过后再接 Ruffle 和引擎切换，扩展到恢复及多窗口。密码库、扩展、自动化和 Agent 各自在相应技术前提确认后开工。

| 阶段 | 退出证据 |
| --- | --- |
| M0 · 可复现的运行时 | 现有 Win x64 运行时功能验收已通过，可供 M1 使用。发布前还需独立复建与正常的依赖校验，确保产物和补丁可追溯。 |
| M1 · 浏览器薄切片 | 一个应用包与真实自编译运行时集成。导航、标签切换、关闭/撤销、引擎切换、输入、焦点、崩溃恢复运行。沙箱、IPC、Session 权限和窗口关闭通过验证。真实产物 smoke 自动执行。 |
| M2 · 测试版 | 书签/历史、会话与下载基础能力通过。存储与清理验证覆盖异常退出。明确兼容矩阵、产物完整性、分发授权、更新及签名处置。公开范围和内核维护承诺通过独立评审。 |
| M3 · 专项能力 | 按独立验收推进后台出帧、视觉和脚本包，以及密码、扩展和下载增强。用同一个已知内核做对照，依结果决定模块的纳入节奏。 |

沿用用户选定的 TypeScript、electron-vite 与 electron-builder 方向，固定工具链和目标运行时。区分构建 Node、内置 Node 和原生模块 ABI。用单元测试验证业务合同，集成测试使用实际存储与进程边界，浏览器 smoke 驱动真实 WCV 和 PPAPI。UI E2E 工具按自编译二进制的实测结果确定。每次把待验证项改为已验收时，附对应的构建标识、配置、案例和输出。
