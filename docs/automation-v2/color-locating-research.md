# Automation 2.0 颜色定位（多点找色）可行性研究

> 日期：2026-09-04
> 状态：研究结论，未立项实现
> 触发：模板匹配在像素风 Flash 游戏的识别率瓶颈 + 钓鱼脚本对"小目标/重合事件"的检测需求

## 1. 目的

评估传统"多点找色"（大漠/按键精灵式）作为 Automation 2.0 第三类定位能力（现有 image 模板 + text OCR）的可行性，回答：

1. 找色对像素风 Flash 目标（鱼/按钮/UI）的命中率与假阳性表现；
2. 相对现有 OpenCV 模板匹配，能否解决"带背景素材分数崩 / 剥离素材 90% 认错"两个痛点；
3. 适用边界（何种目标可行、何种不可行）；
4. 若立项，产品形态与 locator 家族如何接入。

**结论先行**：找色对"≥20px、有独特色彩组合"的目标（如蓝背白肚鱼）**唯一命中、零假阳性，判别力显著优于模板匹配**；对"颜色大众 + 极小"的目标（如金色鱼钩）**单帧不可解**——但钓鱼玩法经重构后钩可绕开"识别"，见 §5。

## 2. 动机与背景

模板匹配在真实素材上的已知失败（2026-08-31 ~ 09-02 诊断）：

| 现象 | 根因 |
|---|---|
| 带背景素材匹配分数 0.77~0.87，低于 0.9 阈值判未找到 | 背景像素（占 34~47%）参与 CCOEFF 归一化，背景一变分数被拖 |
| 背景剥离（转 alpha）后 90% 认错 | 剥离只留形状，mask 分支丢颜色上下文；页面相似形状图标/按钮撞车 |
| OCR 无法识别像素文字 | PP-OCRv3 通用模型对低清像素字召回不足，Pixel OCR 为 Out of Scope |

→ 传统脚本生态（大漠/按键精灵）用"特征点颜色采样 + 固定几何偏移"绕开上述问题：**不比较背景、不依赖形状纹理**，判别来自独有颜色组合。本项目探索同思路。

## 4. 关键实测结论

### 4.1 静态场景：鱼 100% 唯一命中，渲染色差只有一处

| 素材 × 场景 | 命中 | 位置/框 | 分数 |
|---|---|---|---|
| 鱼右 × 2132 场景 | ✅ | (1060,668) 29×22 | 100.0% |
| 鱼（透明）× 2132 场景 | ✅ | (1049,679) 19×13 | 100.0% |
| 鱼右 × 1422 PixPin | ✅ | (761,438) 29×22 | 100.0% |

- **素材与场景鱼同源同色**：深蓝背/浅青鳍/深灰纹全部 100% 召回（早期"配色不符"为误判——看图标错认鱼，实际是同一条鱼）。
- **渲染色差 = 白色偏**：素材白肚 240,240,240 vs 场景纯白 255,255,255（曼哈顿差 45）。容差 34 时白肚 miss、**容差 52 全中**。→ 找色必须按主色容忍渲染色偏（容差 ~50 或参考色自动校准）。
- **场景内鱼 = 素材 0.66×**（两场景同 scale）→ 多档 scale 扫描是必要机制（与模板匹配 scale 飘 0.75 同根源）。

### 4.2 精确锚定：稀有点定候选 + 主色验证

- 纯主色召回会偏左上：主色统计不约束小面积斑纹位置，粉斑被挤出框外。
- 修正：用稀有斑纹色做强锚。鱼身 ff6598 粉点在 2132 全场景仅 4px → 作锚后框移正，**用户确认正中鱼身**。
- 用户提醒：ff6598 虽稀有，游戏 UI 场景偶尔也会出现 → 单稀有点有假阳性风险 → **形态必须是"稀有锚定候选 + N 个主色点按固定几何偏移全中才认"**，散落的 UI 同色点无法同时满足多点几何约束，天然免疫。

### 4.3 适用边界：鱼钩（颜色大众 + 极小）= 单帧不可解

鱼钩 18×20 透明、白/棕/黄大众暖色，全图粗扫出 **8 个远距高分候选区（86%~97%），至少 2 个独立区域精扫后到 100%**——假阳性来自页面顶部 UI 与各处暖色小图标，纯"颜色+固定偏移"信息量不足以区分目标与相似 UI。

→ **找色强在颜色判别、弱在形状判别**。适用目标：≥20px、有独特色彩组合（鱼/按钮/纯色 UI）。鱼钩类目标见 §5 的事件化重构。

### 4.4 视频 1（290×208 局部）：鱼逐帧 100% 跟踪；钩固定列 y 轨迹干净

- **鱼**：色块法逐帧唯一跟踪全 115 帧（x86→176 往返 → 停 (120,143) → f089 被钓走消失）。
- **镜像鲁棒性已实证**：用头朝右素材（鱼.png）跟踪了头朝左游动的鱼全程 100% → 色块召回（窗口内主色像素量）对水平镜像天然鲁棒，无需双朝向素材。（用户确认正常玩法双朝向都会出现。）
- **钩**：x 全程固定 ≈135 列（x131-139）；钩专属色（棕/黄/橙，鱼身上无）在固定列的 y 轨迹干净无歧义：悬停 y≈54 → f053 下行 → f080 y135 → f083 y142-155。
- **用户 ground truth 标定：f083 = 钩住鱼（触发帧）**——"鱼与钩 70% 重合"的帧级像素判据基准。

### 4.5 视频 2（1418×842 完整画面）：玩家角色 = 稳定视觉锚

完整画面揭示了此前"无锚"死结的真正答案：

- **玩家紫色精灵清晰稳定**（浅滩船上，戴紫帽白袍），连钓时位置完全不变，与背景对比强、唯一 → **可作最稳定的视觉锚**。
- 结构：顶部横幅"皮卡堂 大湖"含装饰鱼形图案（鱼找色干扰源，必须 ROI 排除）；左侧/右侧功能图标与表情栏（UI 干扰）；中央玩家 + 金色鱼竿斜向右上（竿尖垂线即钩列，几何恒定）；玩家下方水面 = 鱼活动区（含荷叶/莲花/浮标等装饰）；底部工具栏。
- 帧差实证 f060→f085：钩位置 y≈80→y≈120（钩下行），鱼竿旁出现蓝色感叹号（鱼咬钩提示）→ 阶段 4（鱼动钩静）→ 阶段 5（鱼静钩动）转换清晰。
- 教训：此视频曾被误判"静止"（`fdiff | head -3` 截断输出），后以 timeline 全扫描纠正——**视频分析不得截断差异输出**。

## 5. 玩法重构：重合是事件，不是单帧小目标识别

用户钓鱼流程（6 步状态机）：抛竿 → 上钩（多出赶走钮）→ 点收线 → 阶段 4 鱼左右游钩静止、**鱼到钩正下方点拉杆** → 阶段 5 鱼静止钩上下往返、**钩与鱼重合点拉杆** → 完成。判据：图片 70% 重合。

- 约束：连钓锁玩家（会话内钩列/UI 稳定）；20s 倒计时从进拉鱼即跑；三种鱼体型往返速度不同（节奏计时不可靠）；点错 = 失败需重钓。
- 结论：**鱼钩不做"识别"，做"事件检测"**——钩以玩家为锚（玩家不动则钩列会话内固定，换钓点自动重标定），鱼 = 找色逐帧实时跟踪（对鱼速差异天然免疫，不预测）。
- 设计骨架：玩家锚定位 → 竿尖垂线 = 钩列 → ROI（玩家下方水面）内鱼跟踪 → 钩 y 沿垂线下缘扫 → 重合阈值（f083 标定）触发点击。

## 6. 产品形态草案（待立项，未实现）

- Locator 家族加第三类：`{ kind:'image', asset, method: 'template' | 'color' }`，素材仍是同一张 PNG，**特征点运行时自动提取/缓存**，用户不建新东西 → 四入口（Blockly / JS / 助手 / 测试中心）只透传一个字段，等价性 P0 自动保住；surface/region/坐标/点击链路零改动。
- 特征点提取：稀有锚点（按场景稀有度排序，取 2-3 个，排除全场景不存在的色）+ 主色验证点（避开背景/透明/渐变）。
- 匹配：多档 scale 扫描（含非整数档）+ 锚定候选 + 多点几何全中 + 唯一性判定（最高分显著领先第二名）。
- 防误报硬约束：最少命中点数门槛、多锚投票、多候选报告"不确定"。
- 落地切面（建议分层）：① 匹配引擎（core + vision，纯 Node 可测）→ ② JS/TS + 测试中心开放 → ③ Blockly 下拉补透传。

## 7. 已知边界与未决项

1. ROI 必要性已验证存在（横幅鱼形装饰与真鱼撞 100% 候选）——实机必须限定游戏水面区域。
2. 完整画面（1418×842）ROI 内鱼色块唯一性尚未实测（顶部装饰已在 ROI 外，预计可行）。
3. 玩家紫色精灵的检测方式（色块/模板）与稳定性量化未做。
4. 换钓点后"玩家→竿尖→钩列"偏移恒定性未跨局验证（自学习方案可豁免：每会话开局标定一次）。
5. 动态目标（游动鱼、拉伸动画竿）颜色变化的容差策略需实测标定。
6. 融合路线未探索：找色预筛 + 模板精确认（大漠式混用），可作后续增强。

## 8. 过程教训（避免重蹈）

- 素材与目标"看起来不像"可能是渲染缩放/白偏所致，先做像素级同源对比再下结论，勿凭看图臆断。
- 稀有点作锚必须选"存在但稀有"（频率几十~几百），全场景不存在（频率 0）的色会导致全 miss。
- 白描边封闭提取在低分辨率（290×208）下对 ≤12px 目标失效（描边被背景融断），只在完整分辨率下对大实体成立——不可作为小目标通解。
- 视频差异分析禁止截断输出（head -3 造成过整段误判）。
