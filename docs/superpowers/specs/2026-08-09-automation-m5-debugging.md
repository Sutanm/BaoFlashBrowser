# 自动化 M5：素材预览与识别调试

## 本批结果

M5 第一批让用户在运行完整脚本前验证图片素材：

- 工作台素材列表可点击，并显示受限尺寸的缩略图、原始像素尺寸与文件大小。
- 网页侧栏可选择脚本中的任意素材，设置 50%–100% 识别阈值，并在当前 BrowserView 上执行一次无副作用识别。
- 命中后显示匹配分数、设备像素位置、命中尺寸和 OpenCV 耗时；未命中时给出明确提示。
- 素材测试复用正式运行的后台截图、OpenCV Worker、最小化捕获租约与标签生命周期保护，不执行鼠标或键盘输入。
- 测试期间占用独立自动化会话，禁止同时修改或替换素材包；“停止”会中止识别并释放资源。

## 安全边界

- Renderer 只能用已安装包 ID 与包内素材 ID 请求预览，不能传入文件路径。
- 预览前限制单素材为 16MB、宽高不超过 16384 像素，并由 Electron 解码后缩放至 280×180 以内的 PNG Data URL。
- 素材读取返回副本，Renderer 无法修改主进程中已安装包的原始字节。
- 识别阈值限制为 0.1–1，多尺度限制为 0.25–4 且最多 16 个。

## 验证

扩展后的 `npm run probe:automation-m4` 同时验证素材缩略图、识别测试控件和匹配结果显示。底层最小化识别继续由 `npm run probe:automation-m2` 验证。

## 第二批：单步与运行日志

网页侧栏新增两项调试控制：

- “单步启动”完成就绪检查并执行第一个非容器步骤，然后在下一步骤前暂停。
- “下一步”每次只释放一个暂停点；停止操作会同时中止截图、识别、等待和单步暂停。

运行时会发送 `step-paused` 事件，主进程保留最近 100 条结构化日志。日志包含时间、步骤编号、级别和消息，并记录：

- 当前执行步骤。
- 图片匹配分数与 OpenCV 耗时。
- 脚本自定义日志。
- 完成、停止、就绪检查失败、素材测试失败和执行失败。

发生错误时，侧栏保留最后一个 `currentStep` 与步骤编号，因此用户能同时看到“在哪一步”和“为什么失败”。日志仅存在于当前运行状态，不写入包含网页内容的截图或外部文件。

## 第三批：截图框选与素材生命周期

网页侧栏现在可以直接从当前 BrowserView 制作识别素材：

1. 使用与正式识别一致的隐藏捕获租约抓取当前网页。
2. 主进程保留原始截图，Renderer 只接收最大 900×560 的预览图和随机令牌。
3. 用户在预览中拖动框选，主进程按原图比例换算并裁切。
4. 裁切结果统一编码为 PNG，写入当前 `.baoauto` 包并持久保存。

截图令牌使用 128 位随机值，最多同时保留 3 张原图，并在 2 分钟后主动销毁。框选坐标必须完全位于预览范围内，素材名必须是安全相对路径且以 `.png` 结尾。

工作台素材详情同时增加：

- 从本地图片替换同名素材，解码成功后才写入。
- 删除未使用素材。
- 检查工作流引用；被积木或就绪条件引用的素材禁止删除，并提示先移除引用。

## 最终兼容性矩阵

`npm run probe:automation-m5-engines` 使用与产品一致的 Electron 11 BrowserView，串行验证三条链路：

| 场景 | 最小化截图 | OpenCV 定位 | 可信输入 | 结果 |
| --- | --- | --- | --- | --- |
| 普通网页（`contextIsolation: true`） | 通过 | 98.8% | 点击事件 `isTrusted=true` | 通过 |
| Ruffle（`contextIsolation: false`、禁用插件） | 通过 | 100%，约 41ms | 正式驱动点击；按下态变化 21.19% | 通过 |
| PPAPI（启用插件） | 插件已注册 | 当前机器未渲染 fixture | 生命周期与 CDP 释放通过 | 环境阻塞 |

Ruffle 探针使用真实的 bundled Ruffle 与 SWF fixture，不以普通 DOM 模拟。窗口最小化后由正式 `BrowserViewAutomationDriver` 截图、匹配、换算设备像素到 CSS 坐标并点击，结束时断言 CDP 已释放。证据写入 `release/automation-probe/m5-ruffle-result.json` 与 `m5-ruffle-visual.png`。

PPAPI 项只说明插件注册和生命周期正常，不把“Shockwave Flash 出现在插件列表”视为画面识别成功。当前测试环境无法让 fixture 实际渲染，因此保持显式阻塞，需在能正常播放 PPAPI SWF 的 Windows 目标机上完成发布前人工复验。

## 补充积木：入口与键盘控制

- **无条件启动**：工作流不设置 `readyWhen`，用户启动后无需等待页面素材即可进入就绪状态。
- **组合键**：可勾选 Ctrl、Alt、Shift、Win/Meta，并填写一个主键；保存为既有的 `key-press.modifiers`，因此 JSON 模式和旧脚本格式保持兼容。
- **按住直到图片**：按下指定按键后持续识别素材，直到图片出现或消失，支持超时。运行时使用独立的按下/释放事件，并在成功、超时、停止或识别异常的清理路径中释放按键，避免按键卡住。

“按住直到图片”在 JSON 中使用 `key-hold-until-image`，并复用图像步骤的阈值、区域、多尺度、透明遮罩与轮询字段。其素材引用会参与缺失素材校验与删除保护。

## 补充积木：可组合条件

流程分类新增可嵌套的布尔条件值积木：

- **图片条件**：图片达到指定相似度时为真。
- **并且**：左右条件都成立，支持嵌套为 `1 && 2 && 3`。
- **或者**：任一条件成立，支持嵌套为 `1 || 2 || 3`。
- **不满足**：反转一个条件，可表达“未识别到图片”。

这些条件可以插入：

- **如果条件**：选择“那么”或“否则”分支。
- **等待直到条件**：反复判断组合条件，直到成立或超时。
- **重复直到条件**：每轮先判断组合条件，不成立时执行循环体，并受最大次数限制。

JSON 分别使用 `if-condition`、`wait-condition`、`repeat-until-condition`，条件树使用 `all`、`any`、`not` 与原有 `image-visible`。运行时采用从左到右短路求值，避免已经能确定结果后继续截图识别；条件数组最多 16 项，嵌套深度同时受运行时深度限制。旧 `if-image` 与 `repeat-until-image` 保留兼容。

## 独立 UI 素材测试台

工作台新增“素材测试台”标签页，布局以一张用户指定的目标场景图为主，底部为当前脚本的横向 UI 素材带：

1. 用户导入 PNG/JPEG/WebP 目标场景，中央区域按比例完整显示。
2. 底部显示当前包内全部 UI 素材缩略图，并支持一次选择多个本地图片导入。
3. 点击素材或“开始比对”后，正式 OpenCV Worker 在原始分辨率场景上执行模板匹配。
4. 最佳候选区域直接叠加到中央场景：达到阈值为绿色，低于用户阈值为黄色。
5. 结果栏显示匹配度、原图坐标、命中尺寸、缩放比例和耗时。

测试台支持 75%/100%/125% 多尺度开关、Alpha 透明遮罩和 10%–100% 阈值。识别内部不以用户阈值截断，因此低分时仍能显示最佳候选，便于发现裁剪范围、缩放或透明背景问题。目标图只暂存在主进程内存，使用随机令牌访问，10 分钟过期，最多保留两张；文件上限 32MB、解码后上限 800 万像素。

## 停靠式相框助手与跨标签比对

“悬浮相框助手”改为内置用户脚本，通过用户脚本运行时直接注入 BrowserView 页面，不创建额外 BrowserWindow，也不再占用自动化侧栏空间：

- 助手随每个网页主框架加载，可在“用户脚本”页面启用、停用或查看源码。
- 悬浮窗支持拖动、CSS 原生缩放、收起和关闭；关闭只影响当前页面，停用脚本则全局关闭。
- “捕获比对”只读捕获当前 BrowserView，并在悬浮相框中显示最佳匹配框；捕获前助手会隐藏两帧，避免把自身截入画面。
- “连续监测”每 1.8 秒重新截图并识别当前页面。
- 达到阈值显示绿色框，低于阈值显示黄色最佳候选，并展示匹配度和原图坐标。

专用 `GM.baoAutomation` 权限只授予这个内置脚本 ID，普通用户脚本即使伪造元数据也无法调用。接口只开放包/素材枚举与当前页面截图识别，不开放点击、键盘、输入文本或任意标签访问。

## M5.1 稳定性修复

- Blockly 会把当前尚未提供可视控件的高级字段保存在对应积木数据中；JSON 脚本经过“载入积木→保存”后继续保留区域、多尺度、遮罩、轮询、偏移、修饰键、循环延迟及步骤 ID。
- 素材测试台的静态目标场景与相框实时截图使用独立的临时缓存，相框连续刷新不再淘汰测试台场景。
- 相框和测试台的连续比对按脚本包复用 OpenCV Worker 与模板缓存；空闲 30 秒后自动关闭，避免每 1.5 秒重新加载识别引擎。
- 单独执行“检查就绪”后立即释放 BrowserView 自动化租约与识别 Worker；正式启动时重新检查，避免长期占用标签。
- 停止操作只负责发出取消信号，由原运行链统一释放标签、按键和 Worker；取消不再被随后到达的异步异常覆盖成“运行失败”。

## M5.2 识别与输入可靠性

- `click-image` 新增可选的 `verifyBeforeClick` 与 `maxMovementPx`。启用后会在点击前重新截图识别；目标消失或中心位置移动超限时终止步骤，不发送输入。
- 图片匹配坐标叠加偏移后必须仍位于 BrowserView 内，越界会明确报错，避免输入落到错误区域。
- OpenCV Worker 会计算模板灰度标准差。低对比度素材自动从相关系数匹配切换为归一化差分匹配，并把 `lowVariance` 与 `templateStdDev` 返回测试台提示用户优化裁剪。
- 素材测试台的多尺度搜索可设置最小比例、最大比例与步长，自动生成最多 16 档、范围限制为 0.25–4 的缩放列表。

## M5.3 工作台体验

- `readyWhen` 从单图片条件扩展为完整 `AutomationCondition`。旧单图片入口保持兼容，新增组合条件入口，可直接表达多页面任一就绪、多个元素同时出现或弹窗未出现时就绪。
- 图像相关积木优先使用当前脚本素材列表作为下拉选项，减少手写路径错误；载入旧脚本时会保留当前引用值。
- Blockly 每次实质修改都会按脚本 ID 保存本地草稿并显示未保存标记；切换脚本前确认，正式保存或应用 JSON 后清除草稿。
- AND/OR 积木提供四个直接条件槽，未使用的槽可留空但至少需要两个条件；超过四项继续通过嵌套表达，底层格式仍支持单组最多 16 项。

## M5.4 脚本包与素材工程化

- `.baoauto` 清单新增可选的最低应用版本和能力声明。版本 1 旧包载入时会根据工作流自动补齐图像识别、透明遮罩、多尺度、可信输入、导航与组合条件能力；导出时重新计算，避免声明与实际脚本漂移。未知格式版本会明确拒绝，为后续迁移器保留边界。
- 工作台可关联一个素材文件夹，并通过主进程保存的短期令牌执行增量同步。渲染页看不到本机绝对路径；同步只导入新增或内容变化的图片，不自动删除文件夹中消失但可能仍被脚本引用的素材。
- 每个脚本只保留一个活动目录关联，切换或删除脚本时清理关联，进程内关联总数限制为 16，防止长期使用累积无效路径。
- 素材库支持按文件名或子目录搜索，并显示素材所属目录。测试台缩略图进入可视区域附近后才解码加载，降低大素材包首次打开时的 IPC 和图片解码压力。
- Blockly 的素材下拉选项会合并脚本当前引用，即使素材暂时缺失也不会在载入和保存过程中被其他素材静默替换。

## M5.5 发布前诊断与运行历史

- 工作台提供脚本包检查，汇总步骤数、嵌套深度、素材数与素材体积，并报告缺失素材、空工作流、未引用素材、超大素材库、超大包、复杂工作流、最低应用版本和能力声明漂移。
- 缺失素材或最低应用版本不满足属于阻塞问题；体积、数量和复杂度问题作为预警，不阻止用户继续编辑或导出。
- 正式运行和单步调试到达完成、失败或停止状态后保存历史记录，包括起止时间、最终状态、执行步数和最多 100 条本地化消息数据。仅保留最近 50 次，并可按脚本查看和清除。
- 历史文件位于自动化数据目录，不记录截图像素、输入文本、网址内容或文件夹绝对路径；异常或超过 2MB 的历史文件会被忽略，不影响脚本包载入。
- 进入素材测试台时会在后台预热 OpenCV Worker；打开场景图文件选择器时也会并行确认预热。预热不读取素材、不执行匹配、不占用网页标签，Worker 继续沿用 30 秒空闲回收策略。
