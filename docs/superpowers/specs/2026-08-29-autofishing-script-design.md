# 自动钓鱼脚本设计

## 背景与目标

皮卡堂类 Flash 游戏中有一项钓鱼玩法。玩家站立不动，面向水面，钓鱼 UI（浮标、鱼钩、鱼、状态按钮）以玩家为锚点在固定相对位置出现。需要自动完成一次钓鱼。

用户已验证的关键事实：
- 玩家角色**静止不动**，所有钓鱼 UI 元素（收线/赶走/拉杆按钮、鱼钩垂线、鱼的游动轨道）都以玩家为锚点，位于距离玩家固定的屏幕位置。因此无需跟随玩家移动，只有一次钓鱼会话内元素相对玩家固定。
- 钓鱼 UI 是固定尺寸面板整体平移——面板内元素相对布局固定。
- 黄色"拉杆"字牌（连同旁边的钓鱼竿）可被图片模板稳定匹配，实测得分 0.7~0.9 —— 作为阶段判断的可靠锚点。
- 鱼钩素材小、与鱼竿同色、背景杂，**无法**用模板匹配或 alpha mask 可靠识别。
- 玩家在世界中移动不影响本次钓鱼（钓鱼时玩家站定）。

## 玩家确认的完整状态机

1. **等待鱼上钩**：玩家点击"钓鱼"→ 画面只出现**收线**图标（一个按钮或标志）。
2. **鱼上钩**：收线图标左侧出现**赶走**图标。
3. **点击收线**：玩家点击收线图标 → 进入钓鱼。
4. **鱼左右移动**：一条蓝色小鱼在鱼钩垂线左右来回移动，游到右端"拉杆"字样附近会掉头。**当鱼移动到鱼钩垂线中央、与鱼钩垂直对齐时 → 点拉杆** → 鱼静止不动。
5. **鱼钩上下浮动**：鱼钩在垂直方向上下移动（先下放超过鱼约 4px，再回升）。**鱼钩与鱼重合的瞬间 → 再点拉杆** → 钓上鱼，钓鱼完成。

注：第 4 步的触发条件是"鱼与鱼钩垂直对齐"（鱼走到钩的 X 列附近），不是"鱼走到拉杆字样"（鱼走到拉杆字样会掉头）。第 5 步的触发条件是"鱼钩与鱼重合"（几何接近），与钩的上下方向无关。

## 方案概览

复用平台已有的自动化积木（共 26 种）搭建脚本，**不新增积木、不改动匹配引擎**。核心策略：

- **以"拉杆"字牌（含旁边钓鱼竿）作为可稳定识别的锚点**，识别它就等于定位了整个钓鱼面板的状态（当其出现 = 已进入第 4/5 步）。"收线"图标作为第 1/2 步的锚点。
- 由于玩家静止且图标相对玩家固定，各元素位置可用**相对坐标**（0-10000，相对游戏画面或页面）固定下来，无需实时识别鱼钩。
- 鱼的位置需实时识别（鱼是可识别素材，配合面板区域）用来做"垂直对齐"与"重合"判定；鱼钩用"面板内固定 X 列 + 组合模板"或"仅依赖鱼的位置"估算。

## 识别策略

### 锚点识别（已验证可行）
- **拉杆字牌**：模板 `anchor_pull.png`（黄色字牌 + 邻近钓鱼竿），阈值 0.7，多尺度 `[0.75, 1, 1.25]`，mask `auto`。它在第 4 步及以后出现并保持。
- **收线图标**：模板 `anchor_reel.png`，用于第 1/2 步判断"回到等待上钩"。

### 鱼的位置（需实时识别）
- 鱼素材 `fish.png`（用户已有，勉强可识别）。
- 配合 `高速识图区域`/`限定游戏区域` 把识别范围收窄到鱼游动的水平带，避免背景杂色误判。

### 鱼钩的定位（难点，规避方案）
- 鱼钩 X 固定（玩家静止 → 鱼钩垂线相对玩家固定）。鱼钩的 X 用**面板内固定相对坐标**获取，不识别素材。
- 第 5 步"鱼钩与鱼重合"：用**"钩+鱼"重合瞬间的组合模板** `hook_fish_overlap.png`（用户切一张钩贴近鱼的画面做模板）来判定，或退化为"鱼的位置在钩尖下方固定偏移范围内"。

## 脚本流程（积木序列）

```
[入口] 自动找到游戏画面（feature 串）  ← 或 限定游戏区域
[循环] 一直重复：
  [第1步] 等待图片 收线图标 出现        (wait-image anchor_reel, 超时兜底)
  [第2步] 等待图片 赶走图标 出现        (wait-image anchor_chase, 超时兜底)   ← 可选，用于确认鱼已上钩
  [第3步] 点击图片 收线图标            (click-image anchor_reel)
  [第4步] 等待直到条件 位置关系 成立：
            targetA = 鱼(fish.png)   targetB = 鱼钩垂线点(相对坐标, 固定X)
            relation = vertical(垂直对齐)  tolerance = 5px
          条件满足后 → 点击图片 拉杆 (click-image anchor_pull)
  [第5步] 等待直到条件 位置关系 成立：
            targetA = 鱼钩(组合模板 hook_fish_overlap.png 或 固定X+偏移)
            targetB = 鱼(fish.png)
            relation = overlap(重合)  tolerance = 4px
          条件满足后 → 点击图片 拉杆 (click-image anchor_pull)
  [结束] end 成功
```

## 关键设计决策

1. **不试图识别鱼钩素材**（已确认不可靠）。鱼钩用"玩家静止 → X固定 + 相对坐标"或"组合模板"定位。
2. **以"拉杆"/"收线"字牌做阶段锚点**（可稳定匹配），把复杂的状态判断简化为"锚点是否出现 + 鱼的实时位置"。
3. **垂直对齐判定**：`position-compare` 的 `vertical` 关系（|A.x - B.x| ≤ tolerance）。targetA = 鱼的匹配中心，targetB = 鱼钩垂线的固定相对坐标点。因玩家静止，鱼钩垂线 X 可预先测出（相对游戏画面 0-10000）。
4. **重合判定**：`position-compare` 的 `overlap` 关系（欧氏距离 ≤ tolerance）。targetB = 组合模板 `hook_fish_overlap.png` 匹配结果。若组合模板不可靠，退化为"鱼的 Y 与鱼钩垂线下端固定 Y 之差 ≤ 阈值"。
5. 全程用 `等待条件分支`(wait-condition-branch) 而非 `等待条件`，以便超时时重新回到等待上钩，而不是让脚本失败。

## 待验证项（实现前必须确认）

1. **鱼素材在运行时能否稳定识别**（用户反映仅勉强）。若不行，改用"鱼的相对坐标 + 定时轮询"或颜色特征定位。
2. **收线/赶走图标能否采集并稳定匹配**。
3. **鱼钩垂线的固定 X 相对坐标**需要实测一次（玩家静止时）。
4. 阶段 2 的"赶走"图标是否需要（区分"未上钩/已上钩"）——若收线图标本身区分足够，可省略。

## OCR 像素字调研结论（2026-08-29，暂缓）

目标：识别游戏写死的像素文字按钮（拉杆/收线/赶走），用于判断钓鱼阶段。素材为游戏写死、无其他锚点、无法更换。

### 实验（"拉杆"二字，PaddleOCR-json v1.4.1 / PP-OCRv3 rec，直接喂 BMP）
| 输入 | OCR识别 | 分数 |
|------|---------|------|
| 原尺寸 47×53 | "控"（错） | 0.69 |
| 4× 最近邻放大 | "控托"（错） | 0.57 |
| 4× 双三次放大 | "拉托"（半对：拉对了、杆错了） | 0.43 |

### 根因
- 像素字为硬边缘色块，低分辨率下笔画畸形，PaddleOCR 检测/识别产生歧义。
- 放大能部分救活（"拉"字），但密集笔画字（"杆"）始终歧义，且放大降低置信度（0.69→0.57→0.43）。
- 更小的非像素聊天文字反而可识别（平滑笔画无锯齿），证明问题是"像素化"本身而非尺寸。
- PaddleOCR pipeline 无用户级预处理：帧先缩到逻辑尺寸，long side>960 再压到 960，tiny 字被以原生微小尺寸喂给 DBNet，且 limit_type=max 永不放大。无二值化/对比度/平滑钩子。
- OpenCV WASM（@techstark/opencv-js 旧版）缺 `adaptiveThreshold`/`imencode`，自适应二值化预处理在此库难直接实现。

### 可选升级路径（用户后决定暂缓，转做优质素材）
1. **换 PP-OCRv4/v5 mobile rec 模型**：`PaddleOCR-json` 通过 `-rec_model_dir` 指定（--help 已验证），无需改 exe。v4/v5 mobile 对低分辨率文字显著强于 v3，CPU 内存 +约150~250MB、单次识别几百 ms（钓鱼场景只在阶段切换跑一两次，速度够用）。需用户手动下载模型文件放入 `native/ocr/win64/models/`。
2. **识别前对文字区域 2~4× 双三次放大**（配合更优模型）。
3. 兜底：不依赖认字，用"拉杆/收线"字牌**整块做模板匹配**判阶段（已验证 0.7~0.9 可靠）——这是当前推荐的主方案。

### 转向结论
因模型需下载且像素字仍可能部分认不准，用户决定先制作更优质素材，走**模板匹配判阶段 + 鱼用定时/相对坐标**的现状可行路线。本调研结论保留供后续复用。

## 错误处理

- 任一等待步骤超时：用 `等待条件分支` 的 timeout 分支执行"回到等待上钩"（重新循环），避免脚本整体失败。
- "拉杆"锚点匹配低于阈值时：视为尚未进入第4步，退回第1步重试。
- 连续多次失败：`end result=failure` 提示，不无限循环刷屏。

## 架构边界

- 纯积木脚本（workflow JSON），不新增平台代码。所有逻辑在 `AutomationRuntime`（src/main/modules/automation/runtime.ts）与现有 driver 内执行。
- 加载包：ZIP（manifest.json + workflow.json + assets/）。
- 用户通过工作台（AutomationPage）编辑/导入，用相框助手调试识别。
