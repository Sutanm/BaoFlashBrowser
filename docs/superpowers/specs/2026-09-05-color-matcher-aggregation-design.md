# 识色 + 模板匹配融合判定设计

> 日期：2026-09-05
> 修订：2026-09-06
> 状态：方案设计（待扩充困难负样本并验证，不得直接作为生产判定依据）
> 范围：图像识别层；scale、取材元数据和连续跟踪分别处理。

## 1. 问题与目标

颜色匹配和 OpenCV 模板匹配都能召回目标，也都出现过高分误报：

- 颜色匹配会把相同色板、不同结构的状态栏人物、树叶或按钮局部判成目标，且唯一性校准可能把分数显示为 100%。
- 当前带 alpha 的 OpenCV `ccorr-mask` 会在同亮度或局部轮廓相似的区域产生接近 1.0 的错误候选。
- scale 不正确时，两条路径都会错过真目标，继而选择错误局部峰。

目标不是在两种分数中挑一个较高者，而是：

1. 提高候选召回率；
2. 用独立的结构证据验证候选；
3. 将“匹配质量”“候选歧义”“多算法一致性”分开表达；
4. 在无法确认目标时拒绝点击。

## 2. 已确认事实与失效假设

受控样本曾出现恐龙、角色、鱼钩的颜色路径命中正确位置，也出现 OpenCV 在鱼钩场景中的高分错位。这只能证明两种信号互补，不能证明颜色路径天然更可靠。

真实页面随后补充了决定性困难负样本：

- 人物素材会 100% 命中人物状态栏或详情面板，而不是场景人物；
- 鱼钩素材会命中树叶、状态栏或“收线”按钮局部；
- 目标不存在时，相同特征色仍可形成高分候选。

因此废弃以下假设：

- “识色几乎总命中正确位置”；
- “颜色候选超过 rawScore + margin 门槛即可单独采信”；
- “颜色与 OpenCV 坐标重合即可证明目标正确”；
- “无交集时回退颜色候选仍然安全”。

## 3. 融合架构

### 3.1 第一阶段：候选生成

同一帧、同一 ROI、同一组 scale 上并行执行：

- Color Matcher：擅长召回强颜色、透明、小像素目标；
- Template Matcher：擅长召回结构明显、纹理充分的目标。

两者返回候选并集，而不是只保留交集：

```ts
type VisionProposal = {
  source: 'color' | 'template';
  box: { x: number; y: number; width: number; height: number };
  scale: number;
  rawScore: number;
};
```

同一算法的多尺度近邻候选先做空间聚类，避免同一目标的多个尺度结果互相充当“第二候选”。

### 3.2 第二阶段：候选对齐

候选对齐用于收集一致性证据，不直接判成功。优先使用：

1. 矩形 IoU；
2. 归一化中心距离；
3. 尺寸和 scale 差异。

不再只使用 `max(width,height) × scale × 0.5~1.0` 的中心距离。该容差会随大素材急剧膨胀，可能把两个不同目标错误配对。

### 3.3 第三阶段：结构验证

每个聚类候选必须再次与素材做局部结构比较。验证信号至少包括：

- 前景颜色覆盖和颜色空间分布；
- 轮廓/边缘的相对布局；
- alpha 外围或取材背景中的负特征；
- 完整矩形内的局部块关系，防止只匹配到按钮尾部或人物帽子；
- 候选尺寸与预测 scale 的一致性。

颜色和 OpenCV 同位只作为 `agreement` 加分项，不能绕过结构验证。若两条路径都在同一噪声处出错，结构验证仍应拒绝。

### 3.4 最终决策

最终结果保留分离字段，不再把唯一性提升后的值伪装成图像相似度：

```ts
type VerifiedVisionCandidate = {
  box: Rect;
  scale: number;
  colorQuality?: number;
  templateQuality?: number;
  structureQuality: number;
  margin: number;
  agreement: 'both' | 'color-only' | 'template-only';
  accepted: boolean;
};
```

建议规则：

```text
结构分通过 + 基础匹配质量通过 + 无近似并列候选 → 接受
两算法同位                                    → 增加证据，不自动接受
只有一种算法召回                              → 允许进入结构验证，不直接接受
结构不足、候选近似并列或 scale 不可信          → 拒绝
```

界面可显示“匹配 86% · 候选领先 12%”，但不得把 margin 加成后的内部置信度显示为“相似度 100%”。

## 4. Scale 前置条件

融合判定必须使用正确的目标尺寸。Surface 素材的预测 scale 应采用：

```text
logicalSurfaceRatio × (authoringScaleX / runtimeScaleX)
```

其中 `scaleX = displaySize / logicalSize = 1 / zoom`。取材 zoom=1、运行 zoom=1.5 时，校正项为 `1 / 0.667 = 1.5`。

该精确预测仅适用于带可信 Surface reference 和取材 viewport transform 的素材。外部导入 PNG 没有这些元数据，必须保留有界的多尺度搜索、人工参考尺寸或重新取材方案。

Scale 不可信时可以产生诊断候选，但不能把错误 scale 下的最高局部峰当成生产点击目标。

## 5. 连续跟踪边界

连续跟踪只能在首次结构验证成功后启动：

- 首次锁定失败时，不得用轨迹平滑把错误状态栏或树叶候选“稳定”为真目标；
- 跟踪阶段可以缩小 ROI、使用运动连续性和短时丢失容忍；
- 超过丢失门槛后回到完整的候选生成与结构验证流程；
- UI 连续监测应保留当前帧结果，不用上一帧框冒充当前命中。

## 6. 验证语料与指标

现有路由基准源码实际为 15 个真实用例和 5 个生成用例，共 20 个。2026-09-06 复跑结果为路由 20/20、OpenCV 14/20、颜色 15/20（产物 `routing-poc-2026-09-06T01-50-22-497Z.json`）。缓存中还保留了一份旧版 25 用例的 25/25 结果，但它已不对应当前源码；两者都不能替代困难负样本的上线验证。

必须新增这些带 ground truth 的困难样本：

- 场景人物与状态栏/详情面板人物同时存在；
- 状态栏展开和收起时的鱼钩；
- 真鱼钩、树叶、收线按钮局部及鱼钩不存在；
- 静态鱼钩和竖直运动的连续帧；
- 日夜场景、不同窗口大小、zoom 和 Surface 尺寸；
- 图片组中多个相邻动画帧；
- 同色异形、同形异色、透明精灵和重复实例。

至少记录：

- Top-1 定位正确率与 IoU；
- 目标不存在时的误接受率；
- 正样本召回率；
- 分数校准分桶，检查“显示 100%”是否真的接近 100% 正确率；
- 单帧及连续监测 p50/p95；
- scale、Color、Template、结构验证和时序跟踪的消融结果。

## 7. 实施门禁

在补齐上述语料前：

- `auto` 仍视为实验策略，不宣称“安全自动路由”；
- 当前 20/20 只代表这组小语料回归通过，不能外推生产安全性；
- 不按旧版形态 A/B 直接实现坐标交集锁定；
- 显式 `template` / `color` 可保留用于诊断和专业脚本，但普通用户的默认点击不得依赖未经验证的颜色单路接受。

建议实施顺序：先修正并验证 Scale 元数据链，再实现候选并集与结构验证，最后接入首次锁定后的时序跟踪。

## 8. 第一阶段落地结果（2026-09-06）

已将“识色提案 + 局部结构复核”接入共享颜色 Worker，助手、测试中心与脚本 Runtime 经 `AutomaticVisionMatcher` 使用同一结果：

- 找色阶段保留同一位置的不同 scale 假设，不再提前丢掉颜色分略低但形状正确的倍率；
- 进入结构层前只合并同位置、同倍率的重复提案，减少无意义复核；
- 结构层逐像素计算颜色覆盖、轮廓纯度、轮廓 IoU、色彩排列相关性和边缘相关性；
- 最终接受要求结构分不低于 0.30，且相对第二个独立位置至少领先 0.05；用户降低识别阈值不能绕过该门禁；
- 结构复核允许最多 4px 的局部对齐，用于吸收小素材缩放取整和浏览器插值偏移，最终返回校正后的坐标；
- 被拒绝的作者诊断候选显示结构证据，不再因稀疏特征色齐全而显示误导性的 100%；
- 无显著色彩的灰度素材直接路由 OpenCV，不会先被颜色路径占用后拒绝。

当前真实门禁：

| 门禁 | 结果 | 性能 |
|---|---:|---:|
| 鱼钩连续帧（生产 Worker） | 存在 86/86；不存在误报 0/27 | p50 约 16.4ms；p95 约 27.7ms |
| 静态鱼钩与困难负样本 | 日/夜目标均正确；状态栏/树/无目标均拒绝 | 局部结构复核为毫秒级；全屏提案仍是主要耗时 |
| 自动路由矩阵 | 20/20 | OpenCV 单路 14/20 |

本阶段解决的是候选身份判定，不代表全屏搜索性能已经完成。真实整页的多倍率找色提案仍约 0.1–1.0s；下一阶段应把已学习 scale、首次命中 ROI 与连续跟踪接到提案层，减少全屏扫描次数，同时继续补充状态栏、树、按钮和更多缩放档位的困难负样本。
