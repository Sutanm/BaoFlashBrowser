# 实施计划：查看门禁（view-gate）

> 规格：`docs/superpowers/specs/2026-09-22-view-gate-design.md`（G1–G12）
> 目标：让"查看密码"可用，并以**每次查看都验证**满足防窥屏需求。
> 依赖顺序：V1 → {V2, V3} → V4 → V5。每批独立提交、独立验证。

**V1 与 V2 合并提交的原因**：V1 的策略层要按平台构造后端工厂（`osBackendFor()` 调
`createWinCredUiBackend()`），拆开任一半都编译不过。

### V4 由渲染测试发现并修掉的两个产品缺陷

1. **口令错误时"还剩几次"被顶掉**：错误提示与剩余次数原本互斥显示，用户看不到还有几次机会，
   会在毫无预警下被锁。改为并列显示，仅与"锁定"文案互斥。
2. **倒计时基准陈旧**：落定锁定时只更新 `lockedUntil`、不校准 `clock`，基准仍停在挂载时刻，
   于是显示 01:31 而实际 01:30。改为 `applyLock()` 同时校准两者。

### V2/V5 的本机真机验证结果（脚本与 C# 声明都是从模块里抽出来的原物）

| 用例 | 命令要点 | 结果 |
|---|---|---|
| 自检（当前进程 token） | `BFB_VIEWGATE_SKIP_PROMPT=1` + 空凭据 | `OK granted` ⇒ Add-Type 编译通过、CredUI P/Invoke 声明可用、SID 比对正确 |
| 错误密码 | 同上 + 不存在的账户 | `ERR bad-credential` |
| 域限定名（拆分路径） | 同上 + 不存在的域\\账户 | `ERR bad-credential`（拆分不崩） |
| 子进程不可用 | `BFB_POWERSHELL_CMD` 指向不存在的可执行 | `spawn-error` ⇒ 调用方判 `unavailable`（fail closed） |
| 凭据编组往返 | `CredPackAuthenticationBufferW` 造包 → **生产声明**解包 | 编译通过；`unpack ok=True`、密码原样还原 |

**探针刻意用不存在的账户/域**：`LogonUserW` 的失败会累加到账户的错误密码计数上，
拿真实账户反复跑探针可能触发系统锁定策略。

**仍未验证**：`CredUIPromptForWindowsCredentialsW` 的对话框弹出与取消（1223）路径——
需要人在真机上点一次；失败模式是 fail closed（`unavailable` + 已记原因），不毁数据。

### 本批撞出的两个坑（已写进代码注释与单测）

1. **Windows PowerShell 5.1 按 ANSI 解码 `-Command` 与无 BOM 的 .ps1**：脚本里的中文会破坏
   引号配对、整段语法错误。DPAPI 脚本一直是纯 ASCII 所以从未暴露。
   ⇒ 脚本纯 ASCII；文案与凭据走 stdin（base64+UTF-8）；单测加 ASCII 不变式断言。
2. **`CredUnPackAuthenticationBufferW` 返回全限定名、域字段为空**（实测 `user="BATEST\95470"`）：
   直接喂 `LogonUserW` 未必解析。⇒ 按最后一个 `\` 拆分；UPN 且域为空时用
   `[NullString]::Value` 传真正的 NULL（PowerShell 会把 `$null` 强转成 `""`）。

**接口**
```ts
export const MAX_VIEW_FAILURES = 5;
export const VIEW_LOCK_MS = 30 * 60 * 1000;
export const VIEW_PASSWORD_MIN = 6;

export type ViewAuthCode =
  | 'ok' | 'locked' | 'needs-setup' | 'wrong-credential'
  | 'cancelled' | 'unavailable' | 'none';

export interface ViewAuthResult {
  ok: boolean;
  code: ViewAuthCode;
  remainingAttempts?: number;
  lockedForMs?: number;
  reason?: string;
}

export async function resolveViewGuard(): Promise<ViewGuardStatus>;
export async function authorizeView(secret?: string): Promise<ViewAuthResult>;
export async function setViewPassword(next: string, current?: string): Promise<{ success: boolean; error?: string }>;
export async function resetOsAuthUnavailable(): Promise<void>;   // 设置页"重新检测系统验证"
export function isViewLocked(): { locked: boolean; lockedForMs: number };
export function _setOsBackendForTest(backend: OsVerifyBackend | null): void;
export function _resetGuardStateForTest(): void;
```

**OS 验证后端接口（V2 实现，V1 只需接口 + 假实现）**
```ts
export interface OsVerifyBackend {
  readonly id: 'win-credui';
  available(): Promise<boolean>;
  verify(): Promise<
    | { ok: true }
    | { ok: false; kind: 'bad-credential' | 'cancelled' | 'not-current-user'
        | 'account-locked' | 'unusable-account' | 'denied' | 'unavailable'; reason?: string }
  >;
}
```

**步骤**
- [ ] Step 1: 计数/锁定存储（独立 store `password-view-guard`）+ 纯函数（`nextFailState`、`remainingLockMs`）+ 单测
- [ ] Step 2: 查看密码 set/verify（PBKDF2 250k + `timingSafeEqual`）+ 单测（含长度边界、改密需 current、current 错误计入失败）
- [ ] Step 3: 策略解析 `resolveViewGuard()`（§2 的六行表，含 darwin/linux → `password`）+ 单测
- [ ] Step 4: `authorizeView()` 双路径（password / os-*）+ 降级（G10）+ 单测（假后端）

**门①**：typecheck(main) 0 error；`vitest --project unit` 全绿。
**必须覆盖的断言**：第 5 次失败 → `locked` 且 `lockedForMs ≈ 30min`；锁定期间再试 → `locked` **且计数不变**；
成功后计数归零；`cancelled`/`unavailable`/`account-locked` **不计入**；`set-view-password` 用错 `current` **计入**。

## V2：Windows CredUI 后端

**Files**
- Add: `src/main/modules/view-gate-win.ts`（PowerShell 脚本 + `classifyVerifyOutcome` 纯函数 + `WinCredUiBackend`）
- Add: `tests/password-view-gate-win.test.ts`
- 复用：`keyring-win-dpapi.ts` 导出的 `runPowerShell`（同款子进程纪律：stdin 传参、stdout 首行契约、超时 kill）

**PowerShell 脚本要点**
- `Add-Type` 内联 C#：`CredUIPromptForWindowsCredentialsW` / `CredUnPackAuthenticationBufferW` /
  `CoTaskMemFree` / `LogonUserW` / `CloseHandle`。
- 标志 `0x1 | 0x200 | 0x1000`（GENERIC + ENUMERATE_CURRENT_USER + SECURE_PROMPT）。
- `LogonUserW(..., LOGON32_LOGON_NETWORK=3, LOGON32_PROVIDER_DEFAULT=0, out token)`；
  `Marshal.GetLastWin32Error()` → 错误码。
- SID 比对：`[Security.Principal.WindowsIdentity]::new($token).User.Value` vs `::GetCurrent().User.Value`。
- 输出 `OK granted` / `ERR <机器码>`；**密码绝不进 stdout / 命令行 / 文件**。
- **dev-only 测试钩子**：`BFB_VIEWGATE_SKIP_PROMPT=1` 时跳过对话框，从 stdin 读 `user\npass`
  （空则用当前进程 token）——用于失败路径与 SID 路径的本机自动化验证，不降低安全性（仍需合法凭据）。
- 预算：默认 120s（`BFB_VIEWGATE_TIMEOUT_MS` 覆盖）。取消立即返回。

**步骤**
- [ ] Step 1: `classifyVerifyOutcome(outcome, direction?)` 纯函数 + 单测（1223/1326/1909/1327/1330/1331/1385/spawn/timeout/bad-response）
- [ ] Step 2: PowerShell 脚本 + `WinCredUiBackend`
- [ ] Step 3: **本机实测**（不需用户密码）：
  - `BFB_VIEWGATE_SKIP_PROMPT=1` + 空凭据 → 期望 `OK granted`（验证 SID 比对路径真的通）
  - `BFB_VIEWGATE_SKIP_PROMPT=1` + `user=<当前用户>` + 错误密码 → 期望 `ERR bad-credential`
  - `BFB_POWERSHELL_CMD=/nonexistent` → 期望 `unavailable`

**门②**：typecheck 0 error；`vitest` 全绿；上述三条真机子进程实测结果记录到文档。

**交互**
- 点"眼睛" → 依 `viewGuard.mode`：
  - `os-win`：直接调 reveal，主进程弹系统对话框（渲染层只显示"等待系统验证…"）
  - `password`：面板内模态输入查看密码（`needs-setup` 时改为"设置查看密码"，二次确认 + 后果警告）
  - `none`：提示原因（未建库 / 密钥不可用），不弹输入框
- 失败 → 模态内联错误 + "还可尝试 N 次"；`locked` → 倒计时（mm:ss），到点自动恢复可用
- `cancelled` → 静默关闭（不 toast）
- `unavailable` → 错误提示 + 原因

## V5：真机探针

**Files**
- Add: `tools/probe/probes/22-credui.cjs`（`needsElectron: true`）
- Modify: `scripts/smoke-bundles.cjs`（若需 password-store 构件）

**内容**
- 失败路径自动：错误密码 → `verify=false`、计数 +1；`BFB_POWERSHELL_CMD=/nonexistent` → `unavailable` 且**不计数**
- 1909 分支：不可在本机逼出，用假后端单测覆盖，探针里注明
- 成功路径：**手动一次**（用户输入本机密码）确认 `OK granted`
- 锁定路径：连续 5 次错误 → `locked`，读 `password-view-guard.json` 核对 `lockedUntil`

**门⑤**：探针失败路径全自动通过；成功路径由用户手动跑一次并记录结果。
