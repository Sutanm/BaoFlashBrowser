## 2. Agent-ready 浏览器底座（A1）

A1 属于当前 M2 的基础工作，采用增量重构。为避免“多线并行互相踩”，本轮把它拆成**串行五步**，
每步单独验收、单独留证据：

| 步骤 | 内容 | 状态 |
| --- | --- | --- |
| A1-a | Capability 合同与纯层：`ActorKind`/`ActionContext`、`BrowserTarget`、`TargetRef`（含 `producedBy`）、`ShellRef`、动作与稳定错误码、结构化调用记录、纯校验器 + 合同 harness | **已交付（2026-11-26）**，见[能力合同报告](../reports/2026-11-26-capability-contract.md) |
| A1-b | 提取 Tab / Window / BrowsingContext 注册表（只提取 Capability 需要的部分，不做目录式重写） | **TabRegistry 已交付（2026-11-26）**：代际收口（字段已删）+ 生命周期事件；Window/BrowsingContext 注册表移入 A1-c，与第一个消费者一起做（无消费者不建空壳），见[接线报告](../reports/2026-11-26-tab-registry-wiring.md) |
| A1-c | Capability 服务接线：动作走统一入口、代际可观察、休眠持有租约的标签不被销毁 | 未开始 |
| A1-d | 外壳 UI 的关键标签动作改走 Capability API | 未开始 |
| A1-e | A1 退出条件回填与全量验证 | 未开始 |

**进度（2026-11-26）**：活动租约已落地（`user` 为唯一生产者，`keepAwake` 映射为无期限
`preventsDiscard` 租约，休眠判定统一走 `blocksDiscard()`，标签关闭/窗口关闭/过期均确定性清理），
见[活动租约报告](../reports/2026-11-24-activity-lease.md)。A1-a 交付了合同与校验器，**但尚未接线**：
运行时没有任何代码路径导入它，因此对现有行为零影响（这是刻意的——没有消费者的执行器不建空壳）。
注册表提取、服务接线、UI 适配仍未开始；`session-restore` / `download` / `devtools` / `system`
四种租约 owner 仍只有登记能力，接入时须同时交付 holder 身份与定向清理。

M2 不包含 CDP Hub、Page Map、Automation Runtime、Agent Host、模型 Adapter 或无人值守写操作；这些从 M3 按 A2–A6 独立立项。

## 4. 阶段退出条件

M2 只有同时满足以下条件才能写“已通过”：

1. 第 3 节纳入 M2 的产品范围全部完成，或经明确裁决移出本阶段；
2. 存储、清理、恢复和下载覆盖正常及异常路径；
3. A1 达到退出条件，现有浏览器功能无回归；
4. 应用 smoke、单元测试和成品 smoke 通过；
5. 兼容矩阵、分发范围、签名和发布遗留有明确结论；
6. 回填验收提交、命令输出、证据和未承诺边界。
