# BaoFlashBrowser 自动化脚本使用手册

> 适用于 BaoFlashBrowser 1.1.2。本文面向不需要编程经验的普通用户，也说明 `.baoauto` 脚本包和 JSON 编辑的基本约定。
> 第一次使用积木、完全不了解相似度和条件等概念时，请先阅读[自动化积木零基础说明书](automation-blockly-beginner-guide.md)。

## 1. 它能做什么

自动化平台既可以通过图片素材或 OCR 识别网页、Flash 游戏中的 UI，也可以使用 BrowserView 相对坐标直接点击，再执行移动、键盘、文本输入、滚动或页面操作。相对坐标和识别输入都不依赖真实桌面鼠标，因此程序最小化后仍可继续执行。

Windows x64 有标准版和 OCR 版。标准版不携带 OCR 引擎，适合坐标和图片识别脚本；OCR 版离线识别简体中文、英文字母和数字。含 OCR 积木的脚本在标准版可以查看和编辑，执行时会提示改装 OCR 版。

已经安装标准版的用户不需要卸载，也不需要导出脚本：直接运行同版本 OCR 版安装包覆盖安装即可，用户数据、脚本和素材继续保留。开发环境默认不下载 OCR；先执行 `npm run prepare:ocr`，只要 `native/ocr/win64/PaddleOCR-json.exe` 存在，`npm start` 就会自动启用本地 OCR。

图片识别并不等于理解页面元素。目标外观、缩放比例、透明效果或动画变化太大时，仍可能匹配失败。涉及账号、交易、删除等不可逆操作时，不要只依赖图像自动化。

## 2. 打开工作台

- 打开侧边栏中的“自动化”，点击“打开自动化工作台”。
- 或在地址栏输入 `about:automation`。

工作台左侧是脚本库和素材，中间是积木/JSON 编辑区。“素材测试台”用于把 UI 素材放到一张完整场景图中单独验证。

## 3. 新建第一个脚本

1. 点击“新建脚本”，填写名称和脚本 ID。ID 用于本地目录与脚本包标识，创建后不能直接修改。
2. 添加一张或多张 UI 素材。支持直接选择图片、合并素材目录、关联目录后同步，也支持游戏页内框选取材。
3. 在“积木编辑”中拖入一个入口积木。工作区必须且只能有一个入口。
4. 将执行积木接到入口下面，设置素材、相似度、超时和按键等参数。
5. 点击“保存修改”。需要精确控制时，可切到“JSON 代码”查看、校验并应用工作流。

积木和 JSON 是同一份工作流的两种编辑方式。切换脚本前，工作台会先提交当前编辑器状态；切回原脚本时会恢复该脚本自己的积木。JSON 只有在点击“校验并应用 JSON”并通过 schema 校验后才会写回积木，未应用的文本不会覆盖已保存工作流。

## 4. 积木类型

### 入口

- **无条件启动**：用户启动后直接执行。
- **自动找到游戏画面后启动**：导入悬浮助手复制的游戏画面特征串；运行时跨多层 iframe 寻找对应 Flash、Ruffle、Canvas 或游戏框架，坐标和识图默认以该画面为范围。
- **限定游戏区域**：填写左上和右下相对坐标，启动后直接执行；其下所有识图操作默认只搜索该区域，坐标点击仍使用整个 BrowserView。
- **识图就绪入口**：只有指定图片或组合条件满足时才显示就绪并允许执行。

### 鼠标操作

- 点击、移动、拖拽和位置关系积木默认填写相对坐标，也可从下拉框改选图片素材；必须识图的积木统一显示“请选择图片素材”，选择实际素材后才能保存或运行。
- 长积木按目标和参数分成多行；相似度始终显示，匹配方式、超时和最短检测周期收在积木内部的“更多设置”中。最短检测周期默认 `0ms`，一轮识别结束后立即开始下一轮；调大可以限制检测频率，降低 CPU 占用和风扇噪声。
- 在给定区域内随机选择一个点并点击；默认左键双击，可设置点击次数和边缘留白。
- 将鼠标移动到相对坐标或图片中心。
- 拖拽的起点和终点都可以独立选择坐标或图片，因此支持坐标→坐标、图片→坐标、坐标→图片和图片→图片。
- 横向或纵向滚动页面。

### 键盘与文字

- 单个按键或带 Ctrl、Alt、Shift、Meta 的组合键。
- 按住某个键，直到图片状态或组合条件满足。
- 输入文本。

### 识别与等待

- **高速识图区域**：包住一组积木，只截取指定的小区域进行识图；区域越小通常越快。内部的坐标点击、键盘和页面操作不受限制。
- 等待图片出现或消失。
- 等待指定文字出现或消失；可选“包含”或“完全相同”，并设置最低置信度。
- 点击识别到的文字中心；文字识别也继承入口游戏区域、高速识别区域和当前页面/游戏坐标体系。
- 固定等待一段时间。

### 页面

- 在游戏画面坐标内执行：内部坐标和识图切换到已导入特征所对应的游戏画面。
- 在整个页面坐标内执行：内部坐标和识图切回完整 BrowserView；离开后恢复外层坐标体系。
- 打开网址。
- 刷新当前页面。

### 流程

- 延时。
- `if / else` 条件分支。
- `all`（全部满足）、`any`（任一满足）和 `not`（取反）组合条件，可表达 `1 && 2`、`1 || 2 || 3` 等前提。
- “文字条件”可与图片条件混合组合，例如“识别到登录文字，并且加载图片已消失”。
- 固定次数循环、一直重复、循环直到图片状态满足、循环直到组合条件满足。
- “跳出当前循环”只结束最近一层循环，随后继续执行循环后面的积木；不能放在循环外。
- 等待条件时可分别设置“成功时”和“超时时”的处理流程，超时不必直接终止整个脚本。

### 调试

- 写入运行日志。
- 主动以“正常完成”或“执行失败”结束脚本；失败时可以填写原因。
- 调试运行时逐步继续，便于定位在哪个积木等待或失败。

## 5. 页面内悬浮助手

内置的“自动化相框助手”用户脚本会在普通网页和游戏页左上角显示悬浮球。点击悬浮球展开半透明面板，可在不打开侧边栏的情况下操作：

- **执行**：选择脚本、检查就绪状态、倒数或立即启动、停止，并查看当前步骤和日志。
- **识别**：选择 UI 素材，设置阈值，捕获当前页面并高亮最佳匹配区域；也可连续监测。
- **取材**：框选 UI 素材、获取相对坐标、选择游戏画面、复制特征串或取消当前游戏画面选择。

悬浮球可以拖动到另一侧；面板可收起或淡化。助手和其他页面浮窗在截图、识图及脚本运行期间始终显示，因此请把它们移出需要识别或点击的区域；不需要助手时也可以自行禁用脚本。

如果没有看到悬浮球，请在用户脚本管理页确认“自动化相框助手”已启用，然后刷新目标网页。

## 6. 取材、坐标和游戏画面

1. 在悬浮助手中选择“取材”→“进入框选取材”。
2. 等待当前页面画面出现，拖动框住需要识别的 UI。
3. 系统默认给出 `截取素材_001.png`、`截取素材_002.png` 等递增名称；保存前可以改成更清楚的名称。
4. 名称冲突时可替换原素材，或让系统自动追加编号。
5. 点击“保存素材”或在名称输入框按 Enter。点击画面上方的“取消”退出取材。

取材截图令牌有效期为两分钟。进入取材后应及时框选并保存；超时则重新捕获当前页面。

### 获取相对坐标

1. 在悬浮助手中选择“取材”→“获取相对坐标”。
2. 页面会显示 `0–10000` 的棋盘坐标和跟随鼠标的十字线。
3. 单击目标位置，助手会复制 `X,Y`，例如 `6250,3750`，并立即退出取点模式。该次点击只用于取点，不会传给页面。
4. 在点击积木中保持下拉框为“坐标(点此可选图片)”，把复制内容直接粘贴到坐标框。按 Esc 可以取消取点。

坐标使用脚本的 `1280×720` 虚拟逻辑区域并显示为 `0–10000`。未选择游戏画面时，左上和右下对应整个 BrowserView；选择游戏画面后，对应所选游戏画面的可见边界。取点、取材、素材测试和脚本运行都会在内存中换算，不会主动缩放、移动或重排正在显示的网页；系统显示缩放变化也不需要手工探测。

### 选择游戏画面并复制特征串

1. 打开目标游戏并进入真正需要自动化的游戏状态。
2. 在“取材”页点击“选择游戏画面”。绿色边框表示可直接点击的候选；Flash 覆盖层阻止直接点选时，可从右侧候选列表选择。
3. 确认绿色边框贴合游戏内容，然后点击“复制特征串”。复制结果以 `BFG1:` 开头。
4. 回到工作台，在“自动找到游戏画面后启动”或“在游戏画面坐标内执行”积木中点击“从剪贴板导入特征串”。导入成功后积木显示候选名称和尺寸。

特征串保存的是类型、来源、所在框架和画面尺寸等定位证据，不保存一次性的屏幕位置。脚本运行时重新探测当前页面；原 Flash 节点在登录后被 iframe、Ruffle 或 Canvas 替换时，只有来源或框架证据足够强才允许跨类型回退。候选难以区分时会明确失败，不会随意选择面积最大的画面。

一个工作流当前只绑定一个游戏画面特征。在任意游戏入口或游戏坐标作用域中重新导入，会同步更新该工作区里的其他游戏特征字段；若从 JSON 写入多个不同特征，保存时会拒绝。

选择游戏画面后，助手的“获取相对坐标”会复制**游戏画面坐标**。点击“取消选择”后恢复复制**整个页面坐标**。同一屏幕位置在两套坐标中的数值通常不同。

### 两套坐标如何混用

- 工作流默认使用入口决定的坐标体系：“自动找到游戏画面”入口为游戏坐标，其他入口为页面坐标。
- “在游戏画面坐标内执行”和“在整个页面坐标内执行”只影响各自内部，离开后恢复外层体系。
- 游戏坐标模式下，所有图片识别都裁剪到当前游戏画面；高速识图区域会继续与游戏画面取交集。
- 页面坐标模式下，图片识别可以搜索整个 BrowserView；需要避开网站外壳时，应在该作用域内另设高速识图区域。
- 进入另一套坐标时不会继承外层高速识图区域，因为同一组 `0–10000` 数字在两套坐标中代表不同矩形。

窗口移动不会改变两套坐标。窗口最大化、窗口化或尺寸发生变化时，运行中的游戏坐标动作会先等待 BrowserView 稳定并重新定位游戏画面；网站若因宽度变化自行重排，整个页面坐标仍可能改变。

手工“限定游戏区域”仍可用于无法稳定识别播放器的页面：分别取得游戏画面的页面坐标左上和右下，再填入入口积木。该入口只限制图片识别，坐标操作仍属于整个页面。它不会随播放器移动自动更新，因此不应作为可缩放脚本的首选。

如果不同图片只会出现在游戏区域中的不同位置，可在“识别与等待”分类拖入“高速识图区域”，填写当前坐标体系中的左上和右下坐标，再把相关积木放进它的“执行”槽。每个高速区域只影响自己包住的图片识别；多个区域可以先后使用，嵌套时取交集，离开后自动恢复外层区域。游戏坐标模式会始终再与实际游戏画面取交集，单步区域不能越过游戏边界。图片拖拽的起点和终点都会使用当前高速区域。区域与外层范围完全不相交时，脚本会在保存或运行时明确提示。

高速识图区域必须完整容纳图片素材，并建议在目标四周多留一些移动余量；如果区域比素材本身还小，运行时会立即提示，而不是一直等待到超时。脚本运行期间可以最小化整个程序，但不要切换到另一个浏览器标签或打开工作台标签，否则为避免点击错误页面，当前运行会安全停止。

## 7. 如何制作稳定素材

- 素材应只包含目标本身和少量稳定边缘，不要截入大块背景。
- 动图只截取不变化的静态部分。动画帧变化会显著降低相似度。
- 避免把鼠标悬停高亮、临时提示、计时数字或光效截进素材。
- 不要在取材或运行期间手动修改网页缩放；平台不会替你改变网页缩放，但网站可能因人工缩放或窗口宽度变化重新排版。
- 不同按钮外观相似时，扩大到能区分它们的文字或边框，但不要扩大到易变化区域。
- 先用素材测试台或悬浮助手检查高亮位置。分数高但框错位置仍属于误匹配。
- 悬浮助手“识别”页可以切换到“文字识别”，直接输入目标文字，检查识别框、可信度以及截图和 OCR 耗时；标准版会明确提示改装 OCR 版。

建议从 `0.90` 阈值开始。稳定静态目标可提高阈值；画面有轻微压缩、抗锯齿差异时可逐步降低，但不要为追求“识别到”而忽略误点击风险。

### 透明素材与匹配模式

如果角色或图标周围的游戏背景经常变化，建议将素材处理为带透明背景的 PNG。识图积木和素材测试台提供三种模式：

- **自动遮罩（默认）**：检测到 PNG 存在有效透明区域时只比较不透明主体；普通不透明图片则自动按完整图片比较。
- **透明遮罩**：强制只比较 PNG 的可见主体，适合已经认真抠图的角色、道具和图标。
- **完整图片**：比较素材中的全部像素，适合背景本身也是目标特征的按钮、面板或页面片段。

自动遮罩会丢弃透明和大部分半透明边缘，避免抠图时残留的背景色污染评分。它只能解决背景干扰，不能把面向左侧的角色自动当作面向右侧；方向、姿态或动画帧差异明显时，应分别制作素材并组成图片组，复杂分支也可使用“任一条件”。

### 图片组：处理方向与动画帧

把同一目标的多张变体放入同一个素材子目录，工作台会自动把该目录识别为图片组。例如：

```text
角色/行走/左.png
角色/行走/右.png
角色/行走/上.png
角色/行走/下.png
```

只要子目录中至少有两张图片，识图积木的素材下拉框中就会出现 `角色/行走 (4)`。入口、等待、点击、移动、按住直到、条件和循环积木都能选择图片组。

运行图片组时，平台只截取一次当前页面，然后在同一帧中逐一比对组内素材，采用匹配度最高的结果并对它执行操作。图片越多仍会增加模板计算时间，因此建议每组保持在 2–8 张，只放同一个目标的方向或关键动画帧；不同角色不要混入同组。

## 8. 素材测试台

1. 在工作台打开“素材测试台”。
2. 导入一张完整场景图，或捕获某个标签页作为场景。
3. 在底部素材栏选择要测试的 UI 素材。
4. 选择匹配模式后点击开始比对，查看匹配分数、坐标和场景图上的高亮矩形。

首次比对需要加载并预热 OpenCV，通常会比后续慢；同一场景和素材的重复比对可利用缓存。大场景图可以缩放或滚动查看，不会因为预览区缩放而改变源图匹配坐标。

## 9. 运行、就绪和停止

- 有 `readyWhen` 前提的脚本会先检查条件。条件满足后显示“就绪”，再立即或倒数启动。
- 等待图片的超时只表示在指定时间内没有达到阈值；先确认脚本运行的标签、素材文件、缩放、截图范围和测试台一致。
- 点击积木在图片模式下的“点击前确认”默认关闭。静态且后果重要的按钮可手工开启；动画角色或快速移动目标可能因两次中心变化被拒绝。“最大移动”用于限制允许的变化。
- 浏览器窗口最小化时 BrowserView 仍保持渲染，自动化使用 BrowserView 截图和可信输入，不依赖桌面上的绝对坐标。
- 执行期间可在悬浮助手或自动化侧栏中停止脚本。不要同时启动两个会争用同一标签输入的脚本。

## 10. `.baoauto` 脚本包

`.baoauto` 是自动化脚本的可移植包，包含清单、工作流 JSON 和图片素材。工作台支持导入、导出和“检查脚本包”。导入时会检查格式、脚本 ID、工作流结构、素材路径、文件大小和目录越界；不要手工加入可执行程序或依赖绝对本地路径。

工作流的核心结构如下，实际文件还可包含说明、就绪条件和更多步骤：

```json
{
  "formatVersion": 2,
  "viewport": { "mode": "fixed", "width": 1280, "height": 720 },
  "id": "example-script",
  "name": "示例脚本",
  "root": {
    "type": "sequence",
    "steps": [
      {
        "type": "click-image",
        "asset": "start.png",
        "threshold": 0.9,
        "timeoutMs": 10000
      }
    ]
  }
}
```

JSON 编辑器只接受当前 schema 支持的字段。推荐先用积木生成结构，再在 JSON 中做少量精确修改，并使用“校验并应用 JSON”返回积木视图确认。

## 11. 常见问题

### 测试台识别到了，脚本却超时

确认测试台使用的场景与脚本实际运行标签一致，并检查网页缩放、素材名称和阈值。若目标是动图，重新截取稳定区域。1.1.1 的测试台和运行时使用同一 BrowserView 截图范围；仍有差异时先重新捕获现场画面进行对照。

### 新导入的素材没有出现在助手中

点击“识别”页素材标题旁的刷新按钮。保存取材后当前助手会自动刷新，但在另一个页面或旧标签中打开的助手仍可能需要手动刷新。

### 为什么新页面反复提示脚本执行完成

1.1.1 已修复这一问题。新页面第一次读到历史 `completed` 状态时只更新面板，不弹提示；只有该页面实际观察到脚本从“正在执行”变为“执行完成”时才提示一次。若仍反复出现，请确认内置“自动化相框助手”版本至少为 2.0.3，并刷新页面。

### 首次比对为什么较慢

视觉引擎首次加载和预热有固定成本；后续比对通常更快。工作台会主动预热，但机器性能、图片尺寸和系统负载仍会影响时间。

### 助手遮住了游戏内容

收起为悬浮球、拖到页面另一侧、启用自动淡化，或在用户脚本管理页禁用助手。助手和其他页面浮窗在截图、识图与执行期间保持显示，不会自动闪烁隐藏，因此应由用户把它们移出识别和点击区域。

### 导入游戏画面特征串没有反应

当前版本通过主进程读取系统剪贴板。确认已经在助手中点击“复制特征串”，然后直接点击积木字段；正确内容以 `BFG1:` 开头。积木显示候选名称和尺寸即为成功，不需要把长串手工粘贴进文本框。

### 窗口尺寸改变后游戏坐标还有效吗

自动游戏画面入口和游戏坐标作用域会在窗口变化后重新探测并换算，一般不需要重新取点。手工“限定游戏区域”和整个页面坐标无法抵消网站自身的响应式重排；这类脚本应尽量改用自动游戏画面入口。

### 可以直接编辑脚本文件吗

可以。最稳妥的方法是从工作台导出 `.baoauto`，修改其中的工作流 JSON 后重新导入。务必保留 `formatVersion` 和合法脚本 ID，并在运行前使用“检查脚本包”。

## 12. 当前限制

- 图像模板匹配对缩放、旋转、强动画和大幅色彩变化不具备完整语义理解能力。
- 自动化执行只作用于当前指定的 BrowserView 标签，不控制浏览器外部应用。
- PPAPI Flash 必须在真实兼容站点上做人工回归；不同游戏的插件绘制和输入行为可能不同。
- Electron 11、Chromium 87 和 Flash 均已停止安全更新，只应在可信旧游戏站点或本地内容上使用。
