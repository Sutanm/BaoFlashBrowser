# BaoFlashBrowser Automation 2.0 使用手册

> 适用于 BaoFlashBrowser 1.1.2，按 2026-09-08 源码核对。旧工作台、旧 JSON Step、旧 `.baoauto` v1/v2 和 M0–M5 教程仅作为历史资料，不适用于当前包。

## 1. 能做什么

Automation 2.0 可以在指定的 BaoFlashBrowser 标签中：

- 按相对坐标、图片、图片组或 OCR 文字定位目标；
- 点击、移动、拖拽、按键、输入文字和滚动；
- 打开网址、刷新页面、写日志和发送通知；
- 用条件、循环、变量、等待、OCR 读取和可复用脚本组织流程；
- 通过 Blockly 主流程，或受限 JavaScript/TypeScript 脚本运行同一个 Automation Core；
- 把 workflow、脚本、素材和 profiles 一起导入/导出为 `.baoauto` v3。

自动化只控制应用内明确选择的 BrowserView 标签，不控制桌面或其他程序。图片匹配也不理解业务语义；账号、交易、删除等不可逆操作应保留人工确认。

Windows x64 有标准版和 OCR 版。标准版可使用坐标、图片和颜色识别；OCR 版额外捆绑本地 Paddle OCR sidecar 与模型。开发环境需要先运行 `npm run prepare:ocr`（Windows）或 `npm run prepare:ocr:paddle-linux`（Linux）。

## 2. 打开并认识工作台

从侧边栏打开“自动化工作台”，或在地址栏输入 `about:automation`。当前工作台由这些区域组成：

- 顶栏：选择自动化包、目标运行标签，新建/导入/导出/删除包，运行主入口和保存。
- 左栏“主入口”：当前点击“运行主入口”时执行的 Blockly workflow 或 JS/TS 脚本。
- 左栏“可复用脚本”：包内的 JavaScript/TypeScript frontend，可设为主入口，也可被 Blockly 的“运行脚本”积木调用。
- “管理素材”：导入单张图片或图片组文件夹。
- “测试识别”：在导入的完整场景图上离线测试图片、图片组或 OCR。
- “接口文档”：查看沙箱中的 `bao.*` API。

创建自动化包时，ID 只能使用字母、数字、点、下划线和连字符，并以字母或数字开头。点击“保存”才会持久化当前 Blockly 或脚本编辑内容；切换包或入口前先保存。

## 3. 用 Blockly 创建流程

Blockly 主流程直接保存为 `WorkflowDocumentV3`，没有旧版“JSON 代码”双编辑器。工作区必须有一个入口：

- “无条件启动”：以页面视口为默认范围立即执行。
- “限定游戏区域”：用页面相对坐标限定一个区域。
- “指定游戏画面后启动”：通过页面助手选择并导入画面特征，运行时重新解析当前游戏区域。

常用积木分为：

- 鼠标：点击、移动、拖拽；目标槽可以接坐标、图片/图片组或文字 Locator。
- 键盘：按键、输入文字、滚动。
- 图片与文字识别：构造 Locator，或等待目标出现/消失。
- 坐标与区域：临时切到整个页面、游戏画面或指定区域；离开积木后恢复外层 Context。
- 流程控制：条件、固定次数、`while`、永久循环、等待、`break` 和 `continue`。
- 变量与 OCR：定义/更新变量、比较表达式、判断目标存在、读取文字或数字。
- 脚本与扩展：调用包内 JS/TS 脚本，并把结果保存到变量。
- 页面与调试：打开网址、刷新、记录日志和通知。

Locator 与 Action 是分开的：例如把“图片或图片组”接入“点击”的目标槽，就得到图片点击；同一个图片 Locator 也能用于移动、拖拽、等待或条件。这样不需要为每一种“动作 × 定位方式”维护独立积木。

## 4. 坐标、游戏画面与区域

界面输入的相对坐标仍使用 `0–10000`：左上角是 `0,0`，右下角是 `10000,10000`。运行时会将它们转换到当前页面视口或游戏画面；脚本不会保存桌面绝对坐标。

- 页面坐标覆盖完整 BrowserView 内容。
- 游戏画面坐标覆盖当前解析到的视觉 Surface。
- 区域 Context 只限制其内部的识别和操作范围，并可嵌套取交集。

窗口尺寸、网页缩放、导航或渲染进程更换后，平台会刷新坐标 generation。旧截图上得到的目标不会直接用于新画面；下一次识别或输入会等待当前 viewport 稳定并重新解析。网站自身响应式重排仍可能改变目标位置，因此固定页面坐标应谨慎使用。

页面内“自动化相框助手”可以选择游戏画面、取点和框选素材。它使用独立的窄权限桥，不能访问任意 Electron IPC 或本地文件。助手与其他页面浮窗在截图时保持可见；请把它拖离目标区域，或在用户脚本管理页禁用后刷新页面。

## 5. 素材与图片组

“素材中心”支持 PNG、JPG/JPEG、WebP 和 BMP。一个导入目录中至少两张图片时，工作台会把它显示为图片组；组内图片应是同一目标的方向、姿态或稳定动画帧，不要混入语义不同的对象。

制作素材时：

- 只保留目标和少量稳定边缘；避免倒计时、悬停色、粒子和闪光。
- 透明 PNG 可用于忽略变化背景，但不同方向或姿态仍应分别取材。
- 先在“测试识别”中确认高亮框确实落在正确位置，不要只看分数。
- 从页面助手框选的素材会记录捕获时的 viewport transform。运行缩放不同的页面时，平台先尝试推导倍率，未命中再搜索邻近与常规倍率。

图片定位支持模板、颜色和自动策略。普通 Blockly 使用平台默认的自动路由；JS/TS 可以显式选择策略。自动路由把颜色结果作为候选并进行结构复核，诊断分数不会绕过实际阈值。

## 6. JavaScript / TypeScript frontend

包内可以创建多个 JS/TS 脚本。它们既可设为主入口，也可被 Blockly 调用。TypeScript 在保存/运行链路中转译为 ES2019 JavaScript，随后进入隔离沙箱。

脚本只能通过冻结的 `bao.*` API 使用能力，例如：

```ts
const target = await bao.vision.find({
  kind: 'image',
  asset: 'assets/start.png',
  threshold: 0.9,
});
await bao.input.click(target);
await bao.time.sleep(300);
bao.log.info('已点击开始按钮');
```

准确签名以工作台“接口文档”为准。脚本的权限必须同时满足：源码入口声明、导入时用户批准的 grant、当前构建具备该能力以及单次运行预算。脚本不能直接访问 Node.js、Electron、任意 IPC、文件系统或未授权网络/页面能力。不要把密码或令牌写进可分享脚本。

## 7. 运行、停止与诊断

1. 在顶栏选择一个普通网页/游戏标签作为“运行于”目标。
2. 在左栏确认主入口；需要时点击“更换主入口”。
3. 保存当前修改，再点击“运行主入口”。
4. 从状态栏、侧栏或页面助手查看当前步骤和日志；需要停止时点击“停止”。

同一标签一次只能有一个自动化会话。取消不是简单隐藏状态：平台会等待已按下按键、Worker 请求、沙箱调用、CDP 租约和自动化句柄完成回收后再结束。导航或引擎切换会使旧会话失效，以防继续点击错误页面。

首次图片识别可能包含 OpenCV/颜色 Worker 预热成本；后续通常更快。图片组在同一场景帧上并行处理并共享像素。识别超时时依次检查目标标签、素材、阈值、Context/区域、网页缩放和目标是否被助手遮挡。

## 8. `.baoauto` v3

当前包固定为 `format: "baoauto"`、`formatVersion: 3`。根目录结构为：

```text
manifest.json
workflow.json          # 可选，Blockly 主流程
scripts/*.js|ts        # 可选，可有多个
assets/**              # 可选
profiles/*.json        # 可选
```

`manifest.json` 声明 frontends、主入口、features、脚本 permissions 和所有内容项的 SHA-256。权限 grant 保存在包外，不能通过编辑 manifest 自行获得。旧 v1/v2 包不会自动迁移，导入时会返回 `UNSUPPORTED_FORMAT`。

默认安全边界为压缩包 64 MiB、最多 2,000 项、单项 16 MiB、解压总量 128 MiB。路径必须是安全的相对 POSIX 路径；绝对路径、盘符、反斜杠、空段、`.`、`..` 或完整性不匹配都会拒绝导入。

如需手工修改包，先从工作台导出并保留原副本，修改后重新导入验证。不要加入可执行程序、绝对本地路径或未在 integrity 中登记的文件。

## 9. 当前限制

- 自动图片路由与颜色识别仍按实验能力管理，不能替代真实业务验收。
- 模板匹配不能完整理解旋转、强动画、大幅变形和语义相似性。
- OCR 依赖显式捆绑的本地运行时；标准包不包含 OCR。
- PPAPI Flash 必须在真实兼容站点人工验证；插件注册成功不等于内容已渲染并接受输入。
- Electron 11、Chromium 87 和 Flash 均已停止安全更新，只应访问可信旧站或本地内容。

开发者需要了解 Core、沙箱、包合同和测试命令时，继续阅读 [`modules/03-automation.md`](modules/03-automation.md)。
