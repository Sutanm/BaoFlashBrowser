# 如何委托 AI 制作 `.baoauto` 自动化脚本

这份说明面向使用 BaoFlashBrowser 的普通用户。你不需要先学会 Blockly 或 JavaScript；先用
自己的话说明“什么时候开始、画面发生什么、要点哪里、怎样算成功”，AI 会逐步向你确认。

对应的 AI 工作规范位于
[`skills/baoauto-script-builder/SKILL.md`](../skills/baoauto-script-builder/SKILL.md)。把整个 Skill
目录交给支持 Skill 的 AI，或把该文件作为规则文档提供给其他 Agent。

## 最开始告诉 AI 什么

一次说清下面几项通常就够开始讨论：

- 你想自动完成什么，以及怎样判断成功。
- 脚本开始时游戏处于什么状态。
- 画面依次会出现什么，你希望分别执行什么动作。
- 哪些目标会移动、播放动画、变换方向或区分日夜。
- 失败后应重试、跳过、停止，还是通知你处理。
- 这是新脚本，还是修改现有 `.baoauto`。

可以直接复制这段模板：

```text
我要为【网站/游戏】制作一个 .baoauto。
开始状态：【】
操作顺序：【】
成功标志：【】
可能失败或变化的情况：【】
我已有的截图、视频、素材或旧脚本：【】
```

不用为了填满模板而猜测。不知道的地方直接写“不确定”，AI 应继续问你，而不是擅自补全。

## AI 可能向你索要的素材

AI 每轮应只问最关键的一到三个问题。常用材料包括：

- 每个关键状态的完整游戏画面截图。
- 从动作发生前开始、一直录到成功或失败的短视频，保留原始帧率。
- 同一目标不同方向、动画帧、日夜、悬停或按下状态的图片。
- 目标不存在、容易误认到树木/状态栏/按钮等错误场景的截图。
- 失败附近的运行日志，不需要整份日志。
- 修改旧脚本时的原 `.baoauto` 文件。
- 需要锁定 Flash 游戏区域时，由自动化相框助手生成的 `BFG1:` 游戏画面特征。

如果附件里已经能看出答案，不需要再手工描述一遍。截图或视频中若含账号、聊天、角色名等
隐私信息，可以先遮挡；不要向 AI 提供密码、Cookie 或登录令牌。

## 关于坐标：推荐，但不是强制

对于始终固定在游戏画面某个位置的按钮或区域，推荐先绑定游戏画面，再使用游戏画面内
`0–10000` 相对坐标：左上角为 `0,0`，右下角为 `10000,10000`。这样窗口移动或尺寸变化时，
通常比桌面绝对坐标稳定。

这只是推荐方案，不是 `.baoauto` 的限制：

- 浏览器页面上的固定 UI 可以使用页面相对坐标。
- 会移动或变形的目标更适合图片、图片组、颜色事件、OCR 或时序判断。
- 游戏镜头移动、响应式布局和错误的游戏画面绑定仍会让相对坐标失效。
- 水域等不规则区域不必强行画成矩形；只有确实需要限制搜索或点击范围时才设置 Region。

AI 应向你解释为什么选择某种坐标或识别方式，并明确区分“必须”和“推荐”。

## AI 何时可以开始正式制作

至少需要明确：操作状态机、目标页面或游戏画面、每个动作的触发条件、必要素材、超时/失败
处理方式，以及成功标志。对速度很快的目标，还需要知道识别耗时是否来得及，或者从视频中
测量可复现的时间窗口。

信息足够后，AI 应先给出一份简短制作摘要。你只需检查它有没有把动作顺序、成年/幼年、
日夜、第一次/第二次点击等关键条件理解反了。已经明确的细节不应反复确认。

## 收到脚本后怎么验收

1. 在自动化工作台导入 `.baoauto`，确认预览没有格式、权限或完整性错误。
2. 选择正确的运行标签和主入口；如脚本要求，再绑定游戏画面或选择 profile。
3. 先在无损失场景运行，观察识别框是否落在真正目标上，不要只看相似度百分比。
4. 测试目标不存在、状态栏展开、日夜变化、缩放变化、超时和手动停止。
5. 把失败附近的日志和一段短视频发回给 AI，让它在已确认需求上继续修订。

识图和定时都可能受动画、缩放、机器负载和素材质量影响。AI 应说明已验证范围和剩余风险，
不能因为测试台达到 100% 就声称真实游戏必定成功。
