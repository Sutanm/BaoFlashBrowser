# BaoFlashBrowser 自动化积木零基础说明书

> 适用版本：BaoFlashBrowser 1.1.1。本文专门写给完全没有编程经验、不认识专业名词的用户。你不需要学习代码，也不需要打开“JSON 代码”。只要会使用鼠标拖动、点击和输入文字，就可以跟着完成。

## 1. 先用一句话理解自动化脚本

自动化脚本就是一张写给浏览器看的“办事清单”。

例如，你平时会这样操作：

1. 等待“领取奖励”按钮出现。
2. 点击它。
3. 等待“领取成功”提示出现。
4. 停止。

把这四句话换成积木，从上到下连接起来，就是一个自动化脚本。浏览器会按顺序执行，不需要你编写代码。

## 2. 开始前必须认识的词

### 2.1 脚本

“脚本”就是一套完整操作。一个脚本只做一类事情最好，例如“每日领取”“自动登录”或“等待游戏加载”。不要一开始就把所有操作塞进同一个脚本。

### 2.2 积木

“积木”就是一条操作命令。例如“等待 1 秒”“点击”“按下 Enter”。上下连接表示先做上面的，再做下面的。

### 2.3 入口积木

入口是脚本的起点。每个脚本必须有且只能有一个入口。没有入口，浏览器不知道从哪里开始；放两个入口，浏览器不知道该听哪一个。

### 2.4 图片素材

图片素材是从页面或游戏画面中截取的一小块图片，例如一个按钮、图标或提示文字。浏览器会在当前画面中寻找这张图片。

好的素材应该：

- 只包含需要寻找的目标和少量稳定边缘。
- 不包含倒计时、闪光、鼠标悬停颜色等经常变化的内容。
- 动画目标只截取不动的部分。
- 在脚本运行时保持与取材时接近的页面缩放。

### 2.5 相似度

相似度表示“画面中的目标要和素材像到什么程度才算找到”，范围是 `0.10` 到 `1.00`。

- `1.00`：必须几乎完全一样，最严格。
- `0.90`：默认值，适合大多数清晰按钮。
- `0.80`：较宽松，可能更容易找到，也更容易认错。

第一次制作脚本时保留 `0.90`。如果一直找不到，先检查素材和缩放，不要立刻把相似度降得很低。

### 2.6 超时

超时表示“最多等多久”。超过这个时间仍未满足要求，脚本会报告失败，不会永远卡住。

工作台用“毫秒”表示时间：

| 想等待的时间 | 填写数字 |
| --- | ---: |
| 半秒 | `500` |
| 1 秒 | `1000` |
| 3 秒 | `3000` |
| 10 秒 | `10000` |
| 30 秒 | `30000` |
| 1 分钟 | `60000` |

### 2.7 条件

条件就是一个只能回答“是”或“不是”的问题，例如：

- “开始按钮出现了吗？”
- “加载图标消失了吗？”
- “角色图标和地图图标同时出现了吗？”

条件积木通常是圆角小积木，要插进带有条件空位的大积木里。它不能直接接在普通操作积木下面。

### 2.8 遮罩和匹配方式

带图片的积木一般有三种匹配方式：

- **自动遮罩**：推荐默认使用。透明 PNG 会忽略透明背景，普通图片按完整图片比较。
- **透明遮罩**：强制只比较 PNG 中看得见的主体，适合已经抠掉背景的角色、图标。
- **完整图片**：素材里的每个像素都参与比较，适合背景也很重要的按钮、面板或文字区域。

如果你不知道选什么，就选“自动遮罩”。

### 2.9 图片组

如果同一个目标有多个方向或动画外观，可以把图片放进同一个素材子目录。目录中至少有两张图片时，下拉列表会出现带 `📚` 的图片组。

例如：

```text
角色/走路/左.png
角色/走路/右.png
角色/走路/上.png
角色/走路/下.png
```

选择图片组后，浏览器会在同一张画面中比较所有成员，采用最像的一个。不同目标不要混进同一组。

## 3. 打开工作台并认识界面

1. 打开 BaoFlashBrowser。
2. 展开侧边栏，点击“自动化”。
3. 点击“打开自动化工作台”。也可以在地址栏输入 `about:automation`。
4. 点击“新建脚本”，填写脚本名称和脚本 ID。

脚本名称可以写中文，例如“领取每日奖励”。脚本 ID 建议只用英文字母、数字、点、横线或下划线，例如 `daily-reward`。创建后不要随意更改 ID。

工作台主要分为：

- **脚本库**：选择、新建、复制、导入或删除脚本。
- **素材区**：导入、替换、删除图片素材。
- **积木编辑**：拖动和连接积木。
- **JSON 代码**：代码形式的同一份工作流。零基础用户可以完全不使用。
- **素材测试台**：检查素材能否在完整画面中找到正确位置。

## 4. 积木的基本操作

### 4.1 放入积木

1. 点击左侧分类，例如“入口”“鼠标操作”或“识别与等待”。
2. 按住需要的积木。
3. 拖到中间工作区。
4. 把积木靠近上一块积木的连接口，看到吸附后松开鼠标。

### 4.2 改数字或文字

点击积木中的白色数字框或文字框，输入新内容。下拉选项直接点击选择；复选框打勾表示开启。

### 4.3 删除积木

把积木拖到工作区的垃圾桶。删除带内部积木的大积木时，请先确认里面的积木是否还需要。

### 4.4 放大、缩小和移动

- 使用工作区的 `+`、`-` 按钮或鼠标滚轮缩放。
- 在空白处按住鼠标拖动，可以移动整个画布。
- 积木太多时先缩小，找到入口后再放大。

### 4.5 保存

工作台会暂存正在编辑的积木，但真正完成后仍要点击“保存修改”。切换脚本前也建议先保存。

积木和 JSON 是同一份工作流的两种显示方式。只有点击“校验并应用 JSON”后，JSON 修改才会写回积木。零基础用户不要直接修改 JSON。

## 5. 先完成第一个脚本

这个例子会等待“领取奖励”按钮，点击它，再等待“领取成功”提示。

### 5.1 准备素材

准备两张图片：

- `领取奖励.png`：只截按钮本身。
- `领取成功.png`：只截成功提示中稳定的文字或图标。

把它们导入当前脚本，然后在素材测试台中确认高亮框确实落在正确位置。

### 5.2 搭积木

从上到下连接：

```text
[无条件启动]
  执行
    [等待图片 领取奖励.png 相似度 0.90 自动遮罩 超时 10000 毫秒]
    [点击 领取奖励.png 左键 1 次 相似度 0.90 自动遮罩
     点击前确认 ✓ 最大移动 12 像素]
    [等待图片 领取成功.png 相似度 0.90 自动遮罩 超时 10000 毫秒]
    [记录日志 领取完成]
```

点击“保存修改”，回到目标页面，在悬浮助手中选择这个脚本并启动。第一次测试时不要最小化窗口，先观察每一步是否正确。

## 6. 入口类积木

入口类积木决定脚本什么时候可以开始。三种入口只能选择一种。

### 6.1 无条件启动

**作用：** 用户点击启动后，立即执行下面的积木。

**适合：** 不需要检查页面状态的简单脚本。

**示例：**

```text
[无条件启动]
  执行 [等待 1000 毫秒] → [按键 Enter]
```

**注意：** 如果页面还没有加载好，脚本也会开始。需要等待页面内容时，在下面加“等待图片”。

### 6.2 限定游戏区域

**作用：** 用户启动后立即执行，但下面所有图片识别只在指定的游戏区域中查找。它可以减少游戏外相似图案造成的误识别，也能减少 OpenCV 的搜索量。

左上和右下都使用相对坐标 `X,Y`。左上角是 `0,0`，右下角是 `10000,10000`；可以在悬浮助手的“取材”页面使用“获取相对坐标”。

**示例：** 游戏画面左上角为 `1200,800`，右下角为 `8800,9200`。

```text
[限定游戏区域 左上 1200,800 右下 8800,9200]
  执行 [等待图片 开始游戏.png ...] → [点击 开始游戏.png ...]
```

区域入口只限制等待、点击图片、拖拽、图片条件等识图操作。坐标点击仍然相对于整个网页区域，所以助手复制的坐标可以直接使用。右下坐标必须位于左上坐标的右下方。

### 6.3 识别到图片时就绪

界面文字类似“识别到某图片，相似度 0.90，自动遮罩时就绪”。

**作用：** 只有指定图片已经出现在当前标签中，脚本才进入可执行状态。

**可以设置：**

- 图片素材。
- 相似度，默认 `0.90`。
- 匹配方式。

**示例：** 只有看到“游戏大厅”图标时才运行领取脚本。

```text
[识别到 游戏大厅.png 相似度 0.90 自动遮罩 时就绪]
  执行 [点击 每日奖励.png ...]
```

### 6.4 条件满足时就绪

**作用：** 只有一个或多个条件满足时才允许执行。

**用法：** 把“图片条件”“同时满足”“任意满足”或“不满足”积木插进条件空位。

**示例：** 同时看到角色头像和地图图标，说明已经真正进入游戏。

```text
[条件 [同时满足 [图片 角色头像.png] [图片 地图图标.png]] 满足时就绪]
  执行 ...
```

## 7. 识别与鼠标操作积木

工作台把以下积木分别放在“识别与等待”和“鼠标操作”中。本章放在一起讲，是因为图片识别经常紧接着鼠标操作。

### 7.1 等待图片

**作用：** 不断查看当前画面，直到找到指定图片；找到后继续下一块积木。

**可以设置：** 图片、相似度、匹配方式和超时时间。默认超时 `10000` 毫秒，也就是 10 秒。

**示例：** 等待登录按钮最多出现 30 秒。

```text
[等待图片 登录按钮.png 相似度 0.90 自动遮罩 超时 30000 毫秒]
```

**常见错误：** 把超时填成 `30`，实际只会等待 0.03 秒。30 秒应填写 `30000`。

### 7.2 等待图片出现或消失

界面文字类似“等待图片 某图片 出现/消失”。

**作用：** 等待图片进入指定状态。

- 选择“出现”：等它出现在画面中。
- 选择“消失”：等它从画面中不见。

当前积木使用默认相似度 `0.90`，可以设置匹配方式和超时时间。

**示例：** 点击登录后，等待“加载中”图标消失。

```text
[点击 登录.png ...]
[等待图片 加载中.png 消失 自动遮罩 超时 30000 毫秒]
```

### 7.3 点击

**作用：** 直接点击一个相对坐标，或者在画面中找到图片后点击图片中心。新积木默认使用坐标，执行更快且不需要截图识别。

**可以设置：**

- 下拉框选择“填写坐标”，或者选择一个图片素材。
- 坐标使用 `X,Y` 格式，两个数的范围都是 `0–10000`。
- 左键、右键或中键。
- 点击 `1`、`2` 或 `3` 次。
- 选择图片素材时可以设置相似度和匹配方式。
- **点击前确认**：推荐保持勾选。真正点击前会再找一次，避免目标已经移动。
- **最大移动**：两次寻找的位置最多允许相差多少像素，默认 `12`。

**坐标示例：** 在悬浮助手的“取材”页面点击“获取相对坐标”，再单击目标按钮。假设复制结果为 `6250,3750`，直接粘贴到积木：

```text
[点击 填写坐标 6250,3750 左键 1 次]
```

**图片示例：** 从下拉框选择背包素材并双击。

```text
[点击 背包.png 左键 2 次 相似度 0.90 自动遮罩
 点击前确认 ✓ 最大移动 12 像素]
```

**如何选择：** 固定位置按钮优先使用坐标，速度最快；按钮会移动、页面会滚动时使用图片更稳。涉及购买、删除、交易、账号设置的按钮不要完全交给自动点击。

### 7.4 移动鼠标到坐标或图片

**作用：** 把鼠标移动到固定相对坐标，或者先找到图片再移动到图片中心，不点击。固定位置优先填写坐标；位置会变化时选择图片。

**适合：** 必须先悬停才会显示菜单、说明或高亮的页面。

**示例：** 把鼠标移到“设置”图标，再等待弹出的菜单。

```text
[移动到图片 设置.png 相似度 0.90 自动遮罩]
[等待图片 设置菜单.png 相似度 0.90 自动遮罩 超时 3000 毫秒]
```

坐标悬停示例：

```text
[移动鼠标到 填写坐标 6250,3750]
[等待图片 悬浮菜单.png ...]
```

### 7.5 通用拖拽

**作用：** 按住鼠标，从起点拖到终点再松开。起点和终点各自都可以选择“填写坐标”或图片素材，因此支持四种组合：坐标到坐标、图片到坐标、坐标到图片、图片到图片。

**可以设置：** 起点图片、终点图片、两边各自的相似度和匹配方式、鼠标键、拖动时间以及寻找图片的超时时间。一般保持“左键”和默认 `800` 毫秒即可；游戏不接受太快的拖动时，可以把时间改成 `1200` 或 `1500` 毫秒。

**示例 1：** 把 `A.png` 拖到 `B.png`。

```text
[拖拽图片 A.png 相似度 0.90 自动遮罩
 到 B.png 相似度 0.90 自动遮罩
 使用左键 持续 800 毫秒 超时 10000 毫秒]
```

**示例 2：** 只有识别到 `C.png` 时才拖拽。

```text
[如果 识别到 图片 C.png 相似度 0.90 自动遮罩]
  那么
    [拖拽图片 A.png ... 到 B.png ... 使用左键 持续 800 毫秒]
  否则
    （留空，不做任何事情）
```

**制作素材时注意：** `A.png` 应裁出要被拖动的物体，`B.png` 应裁出放置位置。若拖动后物体会遮住终点，脚本仍可正常执行，因为终点会在按下鼠标之前先完成识别。

**坐标示例：** 从固定位置拖到另一个固定位置，不进行识图。

```text
[拖拽 填写坐标 2500,5000 到 填写坐标 7500,5000 使用左键 持续800毫秒]
```

## 8. 鼠标、键盘与文字输入积木

### 8.1 区域内随机点击

**作用：** 在指定的长方形区域里随机选一个位置，然后点击。默认是左键双击，适合奖励面板、地图空白处或位置不固定但范围固定的目标。

填写两个坐标：左上角和右下角。每次执行积木只随机一次；即使选择双击或三击，多次点击也会落在同一个位置，不会跳到不同位置。

```text
[在区域 左上 2000,2000 右下 8000,8000 内随机 使用左键 点击2次 边缘留白200]
```

“边缘留白”会把可选范围从四边向内缩，避免点到边框。它和坐标一样使用 `0–10000` 相对单位，不是屏幕像素。实际抽到的坐标会写入运行日志，方便检查。若留白太大，导致中间没有剩余区域，保存时会提示错误。

### 8.2 按键

**作用：** 按下并松开一个键。

按键名称使用常见英文写法：

| 键盘按键 | 填写内容 |
| --- | --- |
| 回车 | `Enter` |
| 空格 | `Space` |
| 退出 | `Escape` |
| 左方向 | `ArrowLeft` |
| 右方向 | `ArrowRight` |
| 上方向 | `ArrowUp` |
| 下方向 | `ArrowDown` |
| 字母 A | `A` |
| 数字 1 | `1` |

**示例：** 页面准备好后按回车进入游戏。

```text
[等待图片 按回车开始.png ...]
[按键 Enter]
```

### 8.3 组合键

**作用：** 同时按下 Ctrl、Alt、Shift、Win/Meta 中的一个或多个，再加一个普通键。

勾选需要的辅助键，在最后的文字框中填写主键。

**示例：** `Ctrl+A` 全选。

```text
[组合键 Ctrl ✓ Alt □ Shift □ Win □ + A]
```

Win 在 macOS 上对应 Meta/Command。游戏快捷键是否接受组合键取决于游戏本身。

### 8.4 按住按键直到图片出现或消失

**作用：** 一直按住一个键，直到目标图片出现或消失；无论成功、超时还是取消，平台都会尝试松开按键。

当前积木使用默认相似度 `0.90`。可以设置按键、图片、出现/消失、匹配方式和超时。

**示例：** 按住右方向键，直到看到终点标志。

```text
[按住 ArrowRight 直到图片 终点.png 出现 自动遮罩 超时 15000 毫秒]
```

**注意：** 一定设置合理超时。第一次测试时保持窗口可见，确认方向和停止图片都正确。

### 8.5 输入文本

**作用：** 向当前已经获得输入焦点的文本框输入文字。

**可以设置：**

- 要输入的文字。
- 每个字符之间的间隔。`0` 表示不故意等待；旧网页或游戏漏字时可尝试 `50` 到 `150` 毫秒。

**示例：** 先点击账号输入框，再慢速输入账号。

```text
[点击 账号输入框.png ...]
[输入文本 myname 间隔 100 毫秒]
```

**重要：** 不要把密码写进可分享的脚本。密码应使用 BaoFlashBrowser 的密码本。

### 8.6 滚轮

**作用：** 横向或纵向滚动页面。

- 纵向正数通常向下滚动，负数向上滚动。
- 横向正数通常向右滚动，负数向左滚动。
- `480` 是一次较明显的滚动；小幅滚动可以尝试 `120`。

**示例：** 向下滚动一段。

```text
[滚轮 横向 0 纵向 480]
```

不同页面的滚动速度可能不同，应在目标页面实际测试。

## 9. 页面类积木

### 9.1 打开网址

**作用：** 让当前自动化标签打开一个网页。

必须填写完整网址，并以 `http://` 或 `https://` 开头。

**正确：** `https://example.com/game`

**错误：** `example.com/game`

页面跳转后通常应连接“等待图片”，等新页面真正加载完成。

```text
[打开网址 https://example.com/game]
[等待图片 游戏入口.png 相似度 0.90 自动遮罩 超时 30000 毫秒]
```

### 9.2 刷新当前页面

**作用：** 刷新脚本正在控制的当前页面。

**示例：** 刷新后等待游戏大厅重新出现。

```text
[刷新当前页面]
[等待图片 游戏大厅.png 相似度 0.90 自动遮罩 超时 30000 毫秒]
```

刷新会中断页面当前状态，不要放在没有次数限制的循环中。

## 10. 流程类积木

流程类积木决定“什么时候做”“做哪一边”和“做几次”。

### 10.1 等待一段时间

界面文字是“等待多少毫秒”。

**作用：** 什么也不做，暂停指定时间，然后继续。

**示例：** 点击后等待半秒，让按钮动画结束。

```text
[点击 确认.png ...]
[等待 500 毫秒]
```

固定等待越长，脚本越慢。能用“等待图片”判断页面状态时，优先等待图片。

### 10.2 如果识别到或未识别到图片

**作用：** 根据一张图片当前是否存在，选择执行“那么”或“否则”中的一边。

**可以设置：** 识别到/未识别到、图片、相似度和匹配方式。

**示例：** 如果有“领取”按钮就点击，否则记录“今天已领”。

```text
[如果 识别到 图片 领取.png 相似度 0.90 自动遮罩]
  那么 [点击 领取.png ...]
  否则 [记录日志 今天可能已经领取]
```

“否则”里面可以不放积木，表示条件不符合时什么也不做。

### 10.3 如果条件

**作用：** 根据组合条件选择“那么”或“否则”。

**示例：** 如果同时看到“角色头像”和“每日奖励”，才点击奖励。

```text
[如果条件 [同时满足
              [图片 角色头像.png 相似度 0.90 自动遮罩]
              [图片 每日奖励.png 相似度 0.90 自动遮罩]]]
  那么 [点击 每日奖励.png ...]
  否则 [记录日志 当前不在奖励页面]
```

### 10.4 图片条件

界面文字类似“图片某素材，相似度 0.90，自动遮罩”。

**作用：** 回答“这张图片现在能找到吗？”它本身不执行点击或等待。

**用法：** 插入“条件满足时就绪”“如果条件”“等待直到条件”“重复直到条件”“同时满足”“任意满足”或“不满足”的空位中。

### 10.5 同时满足

**作用：** 连接的条件必须全部为“是”。至少连接两个条件，最多有四个直接空位。

**日常说法：** A 和 B 都满足。

**示例：** 角色头像出现，并且加载图标已经消失。

```text
[同时满足
  [图片 角色头像.png ...]
  [不满足 [图片 加载中.png ...]]]
```

需要超过四个条件时，可以把另一个“同时满足”插入其中一个空位。

### 10.6 任意满足

**作用：** 连接的条件中只要有一个为“是”即可。至少连接两个条件。

**日常说法：** A 或 B 任意一个满足。

**示例：** “胜利”或“失败”任意提示出现，都说明本局结束。

```text
[任意满足
  [图片 胜利.png ...]
  [图片 失败.png ...]]
```

### 10.7 不满足

**作用：** 把里面条件的答案反过来。

- 里面图片出现，结果就是“不满足”。
- 里面图片没有出现，结果就是“满足”。

**示例：** “加载中”图片已经不见。

```text
[不满足 [图片 加载中.png ...]]
```

### 10.8 等待直到条件

**作用：** 反复检查一个组合条件，满足后继续；超过时间则失败。

**示例：** 最多等待 30 秒，直到角色头像和地图同时出现。

```text
[等待直到条件
  [同时满足 [图片 角色头像.png ...] [图片 地图.png ...]]
 超时 30000 毫秒]
```

### 10.9 等待条件并处理超时

**作用：** 在限定时间内反复检查条件。条件满足就执行“成功时”；等到超时仍不满足则执行“超时时”。超时分支执行完后，脚本可以继续，不会自动失败。

**示例：** 等待游戏大厅，成功就点击奖励；超时就刷新页面。

```text
[等待条件 [图片 游戏大厅.png ...] 最多 30000 毫秒]
  成功时 [点击 每日奖励.png ...]
  超时时 [记录日志 大厅加载超时] → [刷新当前页面]
```

如果希望超时后直接判定脚本失败，可在“超时时”放入“结束脚本：执行失败”。

### 10.10 重复固定次数

**作用：** 把内部积木完整执行指定次数，可填写 `1` 到 `1000`。

**示例：** 按空格 5 次，每次间隔 300 毫秒。

```text
[重复 5 次]
  执行
    [按键 Space]
    [等待 300 毫秒]
```

**注意：** 循环内部没有自动等待。若操作太快，请主动加入“等待”。

### 10.11 重复直到图片出现或消失

**作用：** 先检查图片状态；不满足时执行内部积木，然后再次检查，最多执行指定次数。当前积木使用默认相似度 `0.90`。

**示例：** 最多点击“下一页”20次，直到“最后一页”标志出现。

```text
[重复直到图片 最后一页.png 出现 自动遮罩 最多 20 次]
  执行
    [点击 下一页.png ...]
    [等待 500 毫秒]
```

到达最大次数仍未满足时，脚本会报告失败。

### 10.12 重复直到条件

**作用：** 与上一块相同，但停止要求可以是多个条件的组合。

**示例：** 最多执行 10 次，直到“完成”出现，或者“体力不足”出现。

```text
[重复直到条件
  [任意满足 [图片 完成.png ...] [图片 体力不足.png ...]]
 最多 10 次]
  执行
    [点击 执行一次.png ...]
    [等待 1000 毫秒]
```

## 11. 调试类积木

### 11.1 记录日志

**作用：** 在运行记录中写下一句话，不点击、不按键，也不改变页面。

**适合：** 标记脚本运行到了哪里，帮助找出卡住的位置。

**示例：**

```text
[记录日志 已经进入领取页面]
[点击 领取.png ...]
[记录日志 已发送领取点击]
```

不要在日志中写密码、验证码、令牌或其他隐私信息。

### 11.2 结束脚本

**作用：** 立即停止当前脚本，不再执行它后面的积木。

- **正常完成**：脚本记录为成功，适合“已经领取过，无需继续”等情况。
- **执行失败**：脚本记录为失败，并显示填写的原因，适合“体力不足”“页面异常”等情况。

```text
[如果条件 [图片 体力不足.png ...]]
  那么 [结束脚本 结果 执行失败 说明 体力不足]
  否则 [点击 执行一次.png ...]
```

“结束脚本”下面即使在 JSON 中还有其他步骤，也不会继续执行。积木编辑时建议把它放在所在分支的最后。

## 12. 三个可以直接照着搭的完整例子

### 12.1 例子一：看到按钮就领取

```text
[识别到 游戏大厅.png 相似度 0.90 自动遮罩 时就绪]
  执行
    [如果 识别到 图片 领取.png 相似度 0.90 自动遮罩]
      那么
        [点击 领取.png 左键 1 次 相似度 0.90 自动遮罩
         点击前确认 ✓ 最大移动 12 像素]

        [记录日志 领取成功]
      否则
        [记录日志 没有找到领取按钮]
```

### 12.2 例子二：按住方向键走到终点

```text
[条件 [同时满足
         [图片 角色.png 相似度 0.90 自动遮罩]
         [图片 地图.png 相似度 0.90 自动遮罩]] 满足时就绪]
  执行
    [按住 ArrowRight 直到图片 终点.png 出现 自动遮罩 超时 20000 毫秒]

```

### 12.3 例子三：等待加载结束再操作

```text
     点击前确认 ✓ 最大移动 12 像素]
```

## 13. 第一次运行前的检查清单

运行前逐项确认：

- [ ] 工作区只有一个入口积木。
- [ ] 所有要执行的普通积木都连接在入口的“执行”区域中。
- [ ] 条件积木已经插进条件空位，没有单独丢在工作区。
- [ ] 图片下拉框选择的是当前脚本真实存在的素材。
- [ ] 超时数字使用毫秒，例如 10 秒是 `10000`。
- [ ] 点击重要按钮时开启“点击前确认”。
- [ ] 循环有最大次数，循环内部需要时加入等待。
- [ ] 素材测试台的高亮框落在正确目标上，而不只是分数很高。
- [ ] 已点击“保存修改”。
- [ ] 第一次运行保持窗口可见，随时准备点击停止。

## 14. 常见问题

### 14.1 提示“工作区必须且只能有一个入口积木”

工作区没有入口，或者放了两个以上入口。保留一个需要的入口，把其他入口拖进垃圾桶。

### 14.2 提示“条件积木不能为空”

“如果条件”“等待直到条件”“条件满足时就绪”或“重复直到条件”的条件空位没有连接任何条件。拖入一个“图片条件”即可。

### 14.3 提示“并且/或者积木至少需要连接两个条件”

“同时满足”或“任意满足”只连接了一个条件。它们至少需要两个；只有一个条件时直接使用那块“图片条件”。

### 14.4 测试台能找到，脚本却找不到

检查脚本运行的标签是否和场景图来自同一个页面，并检查页面缩放、素材名称、匹配方式和相似度。动画目标应重新截取稳定区域。

### 14.5 脚本点击了错误位置

先停止脚本，然后：

1. 在素材测试台查看高亮框是否正确。
2. 重新截取包含更多独特边缘的素材。
3. 提高相似度。
4. 保持“点击前确认”开启。
5. 减小“最大移动”数值。

### 14.6 脚本运行得太快

在两步之间加入“等待 200 毫秒”“等待 500 毫秒”，或者用“等待图片”代替固定等待。

### 14.7 输入文字时漏字

把“输入文本”的间隔从 `0` 调到 `50`、`100` 或 `150` 毫秒，并确认输入框已经先被点击获得焦点。

### 14.8 循环一直失败

确认停止图片或组合条件确实有机会满足，并在循环内部加入短等待。不要只增加最大次数来掩盖素材识别问题。

### 14.9 切换脚本后积木不见了

1.1.1 已修复脚本切换时的积木/JSON 同步问题。请先保存修改，再切换脚本；如果仍发生，确认应用版本至少为 1.1.1，并保留当前脚本包用于排查。

## 15. 安全提醒

- 自动化只会“看图片并执行操作”，它不知道按钮背后的真实后果。
- 购买、付款、交易、删除角色、删除物品、修改账号等操作必须人工确认。
- 不要在脚本、素材名称或日志中保存密码、验证码和令牌。
- 只导入来源可信的 `.baoauto` 文件；导入后先检查积木和素材再运行。
- 第一次运行新脚本时保持窗口可见，从短流程、小次数开始测试。
- Electron 11、Chromium 87 和 Flash 已停止安全更新，只访问可信旧游戏站点或本地内容。

## 16. 下一步

当你能独立完成“等待图片 → 点击（图片模式）→ 等待结果”后，可以按这个顺序继续学习：

1. 用“如果识别到图片”处理有、没有两种情况。
2. 用“同时满足”和“任意满足”组合多个画面条件。
3. 用“重复固定次数”完成有限重复操作。
4. 最后再使用“重复直到条件”和“按住按键直到图片”。

素材制作、悬浮助手、脚本包导入导出等进阶内容见[自动化脚本使用手册](automation-user-guide.md)。
