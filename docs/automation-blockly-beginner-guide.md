# Automation 2.0 零基础指南（1.1.2）

> 写给**完全没有编程经验**、也不熟悉"相似度""变量"这些词的人。
> 本文只讲 1.1.2 的积木工作台；旧版 1.x 教程（`JSON 代码`、旧调试积木、
> `BFG1:` 之前的老流程）已归档，不要照着做。
>
> 分工：本文负责"看得懂、能拼出第一个脚本"；完整功能与边界见
> [`automation-user-guide.md`](automation-user-guide.md)；JS/TS API 见应用内
> `about:automation` 的文档页。

## 0 先记住四件事

1. **脚本只控制你指定的那一个标签页**，不会动鼠标到桌面上的其他窗口。
2. **坐标不是像素**，是 `0–10000` 的比例：左上角 `0,0`，右下角 `10000,10000`。
3. **素材是"截图"**：先框一块画面存成素材，积木才能"找"到它。
4. **识别不理解游戏**：它只知道"这块图长得像不像"，不知道那是血条还是确认按钮。
   删号、付款、确认类操作，请保留人工检查。

## 1 第一次跑起来（10 分钟）

准备：一个要操作的网页标签已经打开，页面内容能正常显示。

1. 侧边栏 → **自动化工作台**（或在地址栏输入 `about:automation`）。
2. 点 **新建**，给脚本起个名字（例如"测试点击"）。
3. 左侧「主入口」里已经有一块 **无条件启动**；它下面就是"要做的事"。
4. 从左侧分类里拖出 **等待(ms)**，填 `1000`，接到启动块里面。
5. 再拖出 **记录日志**，写一句"hello"，接在等待后面。
6. 顶栏选择目标标签 → 点 **运行主入口**。
7. 看状态栏/日志：出现 "hello" 就成功了。

**为什么第一步不是点击？** 因为"点击"需要一个目标（坐标/图片/文字），先验证
"脚本能跑、日志能看"最省时间。

## 2 工作台长什么样

| 区域 | 作用 |
| --- | --- |
| 顶栏 | 选自动化包、选目标标签、新建/导入/导出/删除、运行主入口、保存 |
| 左栏「主入口」 | 点"运行主入口"时执行的 Blockly 流程或 JS/TS 脚本 |
| 左栏「可复用脚本」 | 包里的 JS/TS 脚本，可设为主入口，也可被积木"运行脚本"调用 |
| 管理素材 | 导入单张图片、图片组文件夹，或从页面框选 |
| 状态栏/日志 | 当前步骤、执行日志、错误信息、停止按钮 |

保存只保存"包"的内容，不会自动运行。运行前务必确认**目标标签**选对了。

## 3 坐标：0–10000 怎么算

界面上所有坐标都按比例输入：

- 左上角 = `0,0`
- 正中间 = `5000,5000`
- 右下角 = `10000,10000`

想点画面中央偏右一点（横向 75%、纵向 50%）→ 填 `7500,5000`。

两种坐标系：

| 坐标 | 范围 | 什么时候用 |
| --- | --- | --- |
| 页面坐标 | 整个网页可视区 | 普通网页按钮、输入框 |
| 游戏画面 | 当前绑定的游戏区域（Flash/Ruffle/Canvas） | 游戏内元素，识图只扫这块 |

用 **限定游戏区域** 或 **指定游戏画面后启动** 后，里面的积木默认用游戏坐标；
用 **使用页面坐标** 可以临时切回整个页面。**在区域 … 中** 再限制一个更小的范围，
可嵌套，取交集。

> 窗口大小、网页缩放、换页之后，坐标会被重新换算。别把一次截图上的像素位置
> 直接当成永久坐标。

## 4 三种启动方式

| 积木 | 什么时候用 |
| --- | --- |
| 无条件启动 | 普通网页操作，默认就是整个页面 |
| 限定游戏区域 左上 … 右下 … | 游戏区域大致固定，用两个角圈出来 |
| 指定游戏画面 … 后启动 | 游戏在 iframe/Flash 里，位置会变；用页面助手选一次画面 |

「指定游戏画面」需要页面助手：打开助手 → 选择游戏画面 → 复制 `BFG1:` 开头的特征串，
粘进积木（或点"从剪贴板导入特征串"）。运行时会**重新解析**当前游戏区域，所以换窗口
大小也能跟上。

## 5 积木速查（9 类，共 38 块）

### 5.1 启动方式

| 积木 | 作用 |
| --- | --- |
| 无条件启动 | 立即执行内部流程 |
| 限定游戏区域 左上/右下 | 把内部流程限制在页面的一块矩形里 |
| 指定游戏画面 后启动 | 绑定游戏 Surface，内部默认用游戏坐标 |

### 5.2 鼠标

| 积木 | 作用 |
| --- | --- |
| 点击 目标 按键 次数 | 左/右/中键，1–10 次 |
| 移动到 目标 | 只移动，不点击 |
| 拖动 从 目标 到 目标 时长 | 按住左键拖过去，时长单位 ms |

**目标槽**可以接三种东西：坐标、图片/图片组、文字。这就是"同一个点击，能点坐标、
也能点图片"的原因。

### 5.3 键盘

| 积木 | 作用 |
| --- | --- |
| 按键 键名 | 如 `Enter`、`Space`、`Escape`、`a` |
| 输入文字 内容 间隔(ms) | 逐字输入；间隔 0 表示尽快 |
| 滚动 横向 纵向 | 正数向下/右，负数向上/左 |

### 5.4 图片与文字识别

| 积木 | 作用 |
| --- | --- |
| 图片或图片组 素材 相似度 | 在画面里找素材，返回目标 |
| 文字 内容 匹配 置信度 | 用 OCR 找文字，返回目标 |
| 相对坐标 x,y | 直接按比例定位，不识别 |
| 等待 目标 出现/消失 超时(ms) | 等到目标出现或消失；超时则报错 |

相似度默认 **0.9**：越高越严格，越低越容易命中但也更容易认错。游戏画面有动画、
半透明或缩放时，可降到 0.85–0.9 试；不要一上来就调到 0.5。

### 5.5 坐标与区域

| 积木 | 作用 |
| --- | --- |
| 使用页面坐标 | 内部临时用整个网页坐标 |
| 使用游戏区域坐标 | 内部临时用绑定的游戏画面 |
| 在区域 x y 宽 高 中 | 只在这块区域内识别/操作（0–10000） |

### 5.6 流程控制

| 积木 | 作用 |
| --- | --- |
| 如果 条件 那么 … 否则 … | 二选一 |
| 重复 N 次 | 固定次数循环 |
| 一直循环 | 直到点停止或"跳出循环"；**里面一定要加等待** |
| 当 条件 时循环 | 条件为真时反复执行 |
| 跳出循环 / 继续下一轮 | 提前结束本次或整个循环 |
| 等待(ms) | 固定等待 |
| 等待 目标 出现/消失 超时 | 条件等待，比固定等待可靠 |

### 5.7 变量与 OCR

| 积木 | 作用 |
| --- | --- |
| 定义变量 名 为 值 | 第一次创建变量 |
| 设置变量 名 为 值 | 修改已有变量 |
| 数字 / 文本 / 布尔 / 变量 | 值插槽 |
| 运算 左 运算符 右 | `+ − × ÷`、比较、`AND/OR`、`++`（文字拼接） |
| 检查 目标 是否存在 保存到 变量 | 结果是"真/假" |
| OCR 读取区域文字 保存到 变量 | 读出文字 |
| OCR 读取区域数字 保存到 变量 | 读出第一个数字 |

类型要对上：变量本来是数字，就不要塞文字进去；`++` 只用于文字拼接。

### 5.8 脚本与扩展

| 积木 | 作用 |
| --- | --- |
| 运行脚本 名 参数 结果保存到 类型 | 调用包内 JS/TS 脚本；参数一个，结果类型四选一 |

脚本适合做积木不好表达的复杂计算；简单流程不要绕这一圈。

### 5.9 页面与调试

| 积木 | 作用 |
| --- | --- |
| 打开网页 URL | 当前标签跳转 |
| 刷新当前页面 | 重新加载 |
| 记录日志 内容 | 写到运行日志，排错主要靠它 |
| 通知 标题 内容 | 发系统通知 |

## 6 识别三兄弟怎么选

| 场景 | 用什么 | 原因 |
| --- | --- | --- |
| 按钮位置固定、页面不变 | 相对坐标 | 最快，但页面一改版就失效 |
| 按钮样子固定、位置会变 | 图片/图片组 | 抗位移，怕缩放和遮挡 |
| 按钮文字清楚、样式会变 | 文字 | 抗样式变化，怕低分辨率/描边字 |
| 同一个按钮有多种皮肤 | 图片组 | 把几种样子放一组，命中任意一个即可 |

**图片组**是"同一目标的多张截图"。导入一个文件夹即成为一组；运行时共享同一帧，
速度比逐个找快。动画目标要只截**稳定部分**，截到动画全程会让相似度大幅波动。

## 7 OCR 的三个积木

1. **文字 … 匹配 …**：找一个文字目标，返回位置，可接给点击/等待。
2. **OCR 读取区域文字**：把一块区域的文字读进变量。
3. **OCR 读取区域数字**：读出第一个数字（会去掉逗号和空格）。

匹配方式：

- **完全**：规范化后必须一模一样；
- **包含**：规范化后包含即可；
- **规范化**：忽略大小写与多余空白的比较路径（当前实现与"包含"共用同一比较逻辑）。

置信度默认 `0.5`，调高更严格。**OCR 只在带 OCR 运行时的包里有**：1.1.2 三个正式包
都内置；只有你自己构建的 `*:standard` 包没有，此时 OCR 积木会报运行时不可用。

## 8 什么时候用"等待"而不是"等待(ms)"

- 页面加载、动画结束 → **等待 目标 出现**（例如等"开始"按钮出现）。
- 已知固定延迟（例如开宝箱 800ms 动画）→ **等待(ms)**。
- **一直循环**里必须至少有一个等待，否则会占满 CPU 并让页面卡死。

超时默认 `10000ms`；超时会报错并停止。宁可超时长一点，也不要"没等到就点"。

## 9 完整例子：等按钮 → 点击 → 读分数

目标：页面加载后等"开始游戏"出现，点它，然后读右上角分数。

1. **无条件启动**
2. 里面放 **等待 文字"开始游戏" 出现 超时 15000**
3. 接 **点击**，目标槽接 **文字"开始游戏"**，左键，1 次
4. 接 **OCR 读取区域数字 保存到 score**（在"在区域 … 中"里框住分数位置）
5. 接 **记录日志**，内容填 `score`
6. 保存 → 选目标标签 → 运行

如果第 2 步超时：先把浮窗助手拖开，再检查文字是否被遮挡、OCR 是否可用
（日志会明确写"运行时不可用"）。

## 10 出问题先查这 8 条

| 现象 | 先查什么 |
| --- | --- |
| 一直提示"素材缺失" | 素材被删或包被替换；重新取材 |
| "脚本已删除" | 被调用的 JS/TS 脚本不在了；换脚本或重建 |
| 图片怎么都匹配不到 | 浮窗遮挡、页面缩放变了、目标有动画；换稳定区域或降低相似度到 0.85 试 |
| 点击位置偏了 | 用了页面坐标却在游戏区域里，或反过来；确认启动方式与坐标上下文 |
| OCR 报"运行时不可用" | 装的是 `*:standard` 包；换正式包 |
| 脚本跑飞/页面卡 | 循环里没有等待；加 **等待(ms)** |
| 换窗口大小后失效 | 用了固定像素思维；改用比例坐标或游戏画面特征串 |
| 状态一直是"准备中" | 目标标签没有可用的 BrowserView（内部页）；换普通网页标签 |

**排错顺序**：看日志最后一行 → 看当前步骤 → 确认目标标签 → 确认坐标/素材 →
再考虑降相似度。不要一次改五个地方。

## 11 术语表

| 词 | 通俗解释 |
| --- | --- |
| 标签 | 浏览器里的一个页面 |
| BrowserView | 页面真正渲染的地方；内部页（设置/脚本管理）没有它 |
| 坐标 | 0–10000 的比例位置，不是像素 |
| 页面坐标 | 整个网页可视区 |
| 游戏画面 | 绑定出来的 Flash/Ruffle/Canvas 区域 |
| 目标（Locator） | "要点哪里"的抽象：坐标、图片、文字都能当目标 |
| 素材 | 一张或一组截图 |
| 图片组 | 同一目标的多张截图 |
| 相似度 | 截图和画面的匹配分数，0–1，默认 0.9 |
| 置信度 | OCR 对"这几个字是什么"的把握，0–1，默认 0.5 |
| 区域 Context | 只在一块矩形里识别/操作的临时范围，可嵌套 |
| 变量 | 存一个值的名字；有数字/文字/布尔/空四种 |
| 主入口 | 点"运行主入口"时执行的东西 |
| 包（`.baoauto`） | workflow + 脚本 + 素材 + profiles 的压缩包 |
| 特征串（`BFG1:`） | 描述游戏画面位置的一段编码文本 |
| 原生助手 | 页面里那个浮窗，不需要启用用户脚本 |
