# Chrome 功能对照清单（BaoFlashBrowser 1.1.2）

> 用途：把 Chrome 用户能感知的功能逐项对照，标出现状与依据，作为 1.1.3 及后续版本的选型依据。
> 口径：以 **1.1.2 源码**为准，2026-11-10 复核至 `3ddb20b`。表中状态来自源码核对。
> 运行时验证的范围见第 14 节。源码与本文冲突时以源码为准。
>
> 版本语义（项目约定）：
> - `1.1.x`：**大补丁级**功能包，可包含具体功能；小修补攒着发，不单独发包。
> - `1.x.0`：**架构级**变更（如 1.0.1 → 1.1.0 由 webview 换 BrowserView，正式确认为浏览器项目）。
> - `1.2.0`：**双内核**（Chromium 87 保 Flash + 最新 Electron 用现代特性）等里程碑级突破。
> - `2.0.0`：**产品定位**变更——放弃 Flash，转向通用浏览器。

### 发布门槛

- 运行 `npm run check`、`npm run test:integration`、`npm run test:e2e`、`npm run test:compat` 和 `npm run test:smokes`。
- 完成第 14 节受影响路径的验收，记录平台、构建版本、复现步骤和结果。Windows 跨窗拖放和 PPAPI / Ruffle 页面分别记录。
- IPC 或数据格式有变化时，覆盖旧配置、旧会话、两个窗口并行操作和取消路径。新增监听遵循项目的回环临时端口及 IPC 约定。
- 发布前核对中英文文案、更新说明和打包产物。Electron 保持项目锁定的 11.5.0。

## 16. 使用方式

1. 在「决定」列填 `1.1.3` / `1.1.4` / … / `2.0` / `不做`；
2. 决定进入 1.1.3 的项，按 `docs/modules/` 的模块边界拆 issue（涉及文件、IPC 通道、测试点、验收）；
3. 每完成一项，按验收结果更新「现状」，注明版本号及已验证的平台或运行路径；
4. 版本发布后同步更新本文与 `docs/README.md` 的索引。
