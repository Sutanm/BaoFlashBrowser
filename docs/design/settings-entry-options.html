语言

设置即时保存，不需要「应用」按钮。

  • 好处：不遮页面本体（面板只占右上角 312 px）、不新开窗口；焦点/Esc/失焦关闭全部复用 M1 已验收的叠加层语义。

设置

语言、下载位置等留给设置面板；这里只放两项最常用的。

  • 好处：改动最小（只改 ShellOverlay.vue + 一条命令），没有新叠加层、没有新权限角色。
  • 代价：面板宽 268 px，主题三项只能用紧凑分段控件；后续加「下载位置、清除数据、书签管理」会挤爆。
  • 风险：设置是全局的，塞在「当前标签的引擎」面板里，心智模型不一致（用户会以为只影响这个标签）。

主题只影响浏览器界面；站点看到的是同一套 prefers-color-scheme。

默认引擎

  • 好处：空间够、能长成完整设置中心（下载、隐私、代理）；不依赖叠加层尺寸计算。
  • 代价：要写第二套窗口生命周期（自绘 chrome、焦点归还、单实例、关窗即丢弃），并新增一个 settings 会话与 IPC 角色。
  • 风险：与「界面归一化」目标冲突——用户会看到第三种 chrome；且设置窗口被页面遮挡时（Flash 全屏）无提示。

说明：这只是造型稿，不含真实存储。点击任一方案的「跟随系统 / 浅色 / 深色」会整页切换，用于比对 token 在两种主题下的观感； 「默认引擎」选中态会跟随点击变化。
